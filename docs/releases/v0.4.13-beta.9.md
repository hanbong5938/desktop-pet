# Desktop Pet v0.4.13-beta.9 release notes

Testing-only beta for rig CPU reduction and hidden-character rendering suspension. This release follows the published beta.8 source and its correction withdrawing the personal Python recovery tool. It does not change stable latest or the authorized migration target, both `0.4.12`. Existing tags and published assets remain immutable. This note describes the candidate and observed checks separately from publication and installed-user acceptance.

## Rig CPU work

Layer-name, group, side and fade classification now happens once per mesh update instead of once per vertex. Mouth expressions prepare their shape once per mesh. Hair preparation caches immutable root, softness and optional bang powers, retaining the original Float quantization, multiplication order, clamps and spring accumulation. Mesh-source inheritance, alpha, local transforms, physics integration, hits and the visible 60 Hz scheduler are unchanged.

The logical strand-weight admission limit and pack format remain unchanged. Packed Double hair coefficients are independently bounded by the existing vertex cap: at most 768 KiB payload per model, a net increase of at most 640 KiB/model or 1.25 MiB for base+pose. Array headers and allocator overhead are separate. Preparation adds work at construction rather than every frame; reset does not reconstruct immutable powers.

## Hidden character

An active hidden host accepts the latest intent and viewport but refuses continuous surface preparation. Queued requests are checked before drawable acquisition, after acquisition and before surface publication. An already running draw may finish during a hide transition but cannot re-enable the hidden surface or hits. Repeated visibility setters leave serial/cache/timer state unchanged.

Showing resumes from the latest intent without replaying missed frames or resetting physics. Inactive candidate preparation, explicit previews and one-time model/recovery preparation remain available while hidden. Bubble, provider and backend work remain independent: hidden process CPU is not required to be zero. No new setting, ABI, FPS option or automatic occlusion policy is introduced.

## Verification tools and evidence boundary

The new production CPU consumer provides `check`, new-file-only `oracle PATH`, bit-exact `compare PATH` and `benchmark`. Its runner compiles identical candidate harnesses against preserved baseline and candidate source, checks semantic/resource regressions, compares explicit Float/Double bit patterns and runs 12 alternating paired benchmark samples with checksum/performance gates. A candidate-only invocation does not claim improvement.

The real `RigNativeHost` AppKit/Metal consumer checks inactive-hidden bootstrap, baseline active-hidden rendering, hidden suspension, three synchronized hide races, latest-intent/viewport resume, duplicate setters, ten visibility cycles, hidden preview, bounded recovery, cancellation and hidden catalog switching. Test counters and synchronization gates are compiled only under `RIG_HOST_VISIBILITY_CHECKS`, not in shipping binaries. Missing GUI/Metal/drawables fail instead of skip-success. See [development checks](../development.md#rig-cpu-and-hidden-host-checks).

The initial pre-port rig implementation passed 3,648 bit-exact records, semantic/resource regressions, 11 real-host scenarios and 81 exact decoded preview pairs. Those measurements used the older Herdr application shell, not this versioned Core beta; they are not relabeled final-beta app or user-installation evidence. The canonical beta baseline's three rig source hashes were confirmed identical before porting. Final beta source/workspace, package and public-byte evidence must be observed separately.

Observed on the canonical beta.9 source before tagging: TypeScript, **62 Bun tests / 532 expectations**, Rust formatting, **878 native workspace tests** (one ignored entry), shell syntax and exact-tag release-note/metadata admission passed. The freshly compiled CPU consumer again compared **3,648 bit-exact records** against preserved beta.8 rig source; all semantic/resource checks passed. Twelve alternating pairs passed checksums/performance gates: hair aggregate candidate/baseline median ratio **0.473** (12/12 faster), mixed ratio **0.638**. Hair construction medians rose by about 1.3–2.8 µs for these 182-vertex fixtures. Fresh real-host runs reproduced the baseline hidden rendering and passed all **11 candidate lifecycle scenarios** using the canonical beta runtime's signed decoder. These are local source/runtime results, not a universal speedup, final CI result or installed-user GUI acceptance.

Actual menu visibility-switch interaction, continuous on-screen motion and physical head/body clicks remain **UNEXERCISED**: the macOS session was locked and both window capture paths failed. No session unlock or bypass is performed. Offscreen previews and synchronized Metal checks are not physical GUI certification.

## Distribution and unchanged contracts

The neutral app, Core and paired coordinator use `0.4.13-beta.9`. Protocol 4, observation 2, integration API 1, migration handover protocol 1, shared contracts `0.1.0`, legacy bridge identity `0.3.16`, adapter pins and beta Download-not-Apply policy are unchanged. No new bridge, plugin, migration, recovery feature, manager ownership takeover or stable Homebrew rollout is included.

Standalone installation retains the actual OS account home's `.local/share/desktop-pet/libexec/DesktopPet.app`; Homebrew and source retain their existing owners. Ordinary installation does not relocate an old Applications owner. The personal Python recovery script remains withdrawn and is not shipped in this release or its checksums. Do not use an old withdrawn copy. Private one-time recovery remains separate from product distribution.

The exact [beta.9 prerelease page](https://github.com/hanbong5938/desktop-pet/releases/tag/v0.4.13-beta.9) is the publication endpoint, never stable latest. Publication uses prerelease=true, make_latest=false and no-overwrite. Its six assets are:

2. `DesktopPet-v0.4.13-beta.9-macos-arm64.tar.gz.sha256`
3. `SHA256SUMS`
4. `DesktopPet-v0.4.13-beta.9-rig-native.json`
5. `desktop-pet-install-v0.4.13-beta.9.sh`
6. `desktop-pet-install-v0.4.13-beta.9.sh.sha256`

Verify the archive and installer against their individual checksums, all three payloads against `SHA256SUMS`, then the exact signed deployed resource closure against the external rig sidecar. The archive contains only `DesktopPet.app`. Signing is local ad-hoc, not Developer ID or notarization. Publishing and downloading do not install or restart an existing user app; use an explicit beta installation path only after saving drafts and following the established owner/profile admission policy.
