# Desktop Pet v0.4.17-beta.9 release notes

## Verified completed history and explicit CLI beta recovery

This testing-only prerelease follows [beta.8](v0.4.17-beta.8.md). Stable v0.4.16 remains latest. Published tags, assets and historical evidence are not replaced. Installing or explicitly recovering to this beta does not enable automatic beta updates.

- A completed-history proof and a concurrent recovery observer can contend for the same operation lease. Once exact settlement is proven, discard obsolete recovery errors and callbacks for that same record instead of keeping Settings in “Recovery blocked.” Outstanding work, occupied reservations, changed contexts and unproven history remain blocked. Historical completion never authorizes a new installation or Start.
- Recognize verified stopped-source installation history without misreporting it as an automatically applied update. A later ordinary Start remains separately authorized and fenced; the original installed-only record is preserved.
- Offline `update-status` locates the retained helper in the product's real update namespace (`updates-v4` for neutral, `updates` for legacy). Finding a private file is not reported as signature verification.
- Same-version native relocation supplies the actual OS-account HOME to its isolated helper. Its source comparison normalizes only the presentation locale; executable, image, version, incarnation, origin, profile, environment and assets remain exact. Stable-parent and native-consent requirements for that path do not change.
- Add a separately opted-in, stopped-source **operator beta recovery**. A version-2 request with confirmation `replace_original_app_preserve_profile_allow_beta` selects a strictly newer official beta. Existing version-1 requests retain stable-only semantics. The immutable plan binds the explicit beta approval to the release and original profile; official archive evidence, signed-resource closure, matching helper version, ownership, generation and reservation checks still apply.

## Operator recovery without controlling the desktop

Use the exact signed helper from the selected release with the private request described in the [CLI contract](../cli.md). This is not a generic `--yes` bypass and does not copy a bundle over a running app. Back up the original app and profile, explicitly stop only Pet, and submit the captured original context plus the verified release evidence. The target is the actual account home's `.local/share/desktop-pet/libexec/DesktopPet.app`.

The operation opens no native approval window and finishes installed but stopped, with no restart authority. Only after the exact operation releases its reservations may a separately approved normal Start run the same original profile. The existing Tern consumer validates native settlement and updates only its saved executable; no manual KV rewrite, Configure/Connect, Tern restart or journal deletion is part of recovery. Native installation and fresh per-window Tern binding are separate verification steps.

For new standalone installs, use the private canonical installation path. Beta.8's example consumer-install command naming `~/Applications/DesktopPet.app` was historical-path guidance, not the destination of a new standalone installation. Resolve the verified installed app before installing its bundled consumer; do not assume the old path exists after recovery.

## Verification and compatibility

Deterministic regressions cover both orders of the completed-history proof/recovery callback race, historical evidence preservation, reservation blocking, installed-stopped history, private-helper discovery, locale-only normalization and explicit beta recovery admission. The exact-tag release workflow gates the locked native workspace, composition tests, TypeScript, release/rig tests, deformation, formatting, signed arm64 packaging, capabilities, default character and signed-resource digest closure. Public release requires qualification of the downloaded draft artifacts; a passing source test or a published archive alone is not proof that a user's profile was recovered.

Before publication, the coordinator suite, 90 updater-state tests, 25 status-filtered core tests and the legacy helper-namespace regression passed locally without GUI automation. TypeScript and 68 script/rig tests passed. A CLI-only smoke exercised the corrected production updater model against the actual running beta.8 and retained completed history: settlement was admitted, recovery/journal errors were absent, and English/Korean models were unlocked and allowed checking. That diagnoses the retained history; it is not a claim that beta.9 was already installed or that the screenshot's precise thread scheduling was observed. Temporary diagnostic source was removed from the release.

The bundled Tern plugin remains **0.2.2-beta.2**, immutable revision `bd0916b62117569a846aacf9c641d74d23799eb7`; its window code and the prior beta.8 session recovery behavior are unchanged. Herdr remains pinned to `0b9e24b2f6498311229a328ad144a4ab41b7505b`. Contracts 0.1.0, legacy 0.3.16, updater protocol 4, observation 2, integration API 1, migration handover 1 and `MIGRATION_TARGET_VERSION=0.4.12` are unchanged. No physical keyboard, IME or VoiceOver acceptance is claimed by these updater regressions.
