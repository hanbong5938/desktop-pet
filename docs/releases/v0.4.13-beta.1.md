# Desktop Pet v0.4.13-beta.1 release notes

Status: **Beta prerelease — opt-in testing, not a new stable release.** This settings and session-clarity release follows stable v0.4.12. Beta software may be unstable or contain bugs. Publishing this prerelease must not replace GitHub's stable latest release, stable installer pointers, or the stable Homebrew formula.

## Changes

- Simplify settings so routine controls are easier to find and secondary app-update options can be expanded when needed. Keep beta-update consent explicit and explain that changing the setting does not install or restart the app.
- Clarify session and connection wording so users can distinguish displayed session information from the integration that supplies it.
- Provide Quit wording, explanatory help, and usage documentation in English, Korean, Japanese, and Simplified Chinese. Quit stops Desktop Pet only; Herdr and Tern keep running, and automatic-start preferences remain unchanged.
- Retain the published v0.4.12 discover/start performance correction: reuse an already verified installation owner within one launch and avoid validating the same physical bundle twice during inspection. Startup context, migration authorization, updater reservations, and Stop fences are still checked.

## Scope and compatibility

No QR feature is included. This release does not change session routing, provider selection, connection protocols, migration authorization, or the bundled Herdr/Tern integration revisions. Session presentation changes are not evidence of a new routing or reconnection capability.

The neutral app, Core package, and paired update coordinator are version `0.4.13-beta.1`; shared contracts remain `0.1.0`. Product identity remains `DesktopPet.app`, `io.github.hanbong5938.desktop-pet`, and `desktop-pet` / `desktop-pet-update-coordinator`, with protocol 4, observation capability 2, integration API 1, and migration handover protocol 1. No legacy bridge release is authorized by this beta.

Direct installation accepts canonical `beta.N` product versions as well as stable versions, using normal version ordering and the existing ownership and installation fences. Stable-only historical migration authorization and standalone updater release-staging restrictions are unchanged; beta installation does not qualify an old-source migration route.

## Validation and known limitations

Final integrated beta source passed TypeScript checking, 62 tooling/web tests, the complete native workspace suite, Rust formatting checks, and the optimized native build. The built app and paired helper both reported `0.4.13-beta.1`, neutral identity, protocol 4, observation capability 2, and integration API 1. The version-pinned release-note admission check also passed.

**Native visual review and full Core-to-Tern end-to-end validation were blocked by the locked screen and were not completed.** Automated success does not establish native layout quality, actual session reconnection, fresh SDK binding, migration/retirement completion, or recovery on another computer. These remain beta limitations, not verified acceptance claims.

These checks include beta versioning, direct-install admission, stable-only migration-target separation, and the retained published performance correction. Public tag provenance, clean tagged packaging, and published asset checks remain separate CI/publication gates; local build checks do not claim installation into a user's app.
