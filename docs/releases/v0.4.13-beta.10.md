# Desktop Pet v0.4.13-beta.10 release notes

Testing-only corrective beta following public `v0.4.13-beta.9`. It restores an explicitly opted-in update path for verified same-owner private Standalone installations, preserves useful Tern failure diagnostics and offers official installation instructions when an executable update is unavailable. Stable latest and the authorized migration target remain `0.4.12`. Existing tags and published assets remain immutable. This note separates prior local source evidence from final beta.10 qualification, publication and installed-user acceptance.

## Same-owner beta update correction

A newer official beta may use the existing signed staging/replacement path only when beta updates are opted in, the installed application is a verified private Standalone installation with the same owner and exact admitted root, and the user gives separate native update consent. This narrowly supersedes the historical beta Download-not-Apply policy for that admitted path; discovering a beta or enabling beta discovery alone is not installation authority.

Stable-only selection remains stable-only. Homebrew retains its stable-formula admission and existing ownership; source and unsupported/manual installations do not gain Standalone replacement authority. Signed resource closure, version and owner checks, Stop generations, reservations and readiness requirements remain enforced. This does not add migration authority, manager takeover or a Homebrew beta rollout.

## Tern diagnostics and installation guidance

Both Tern binding consumers decode backend failure envelopes before strict success-evidence validation. A normal control failure containing `alpha_passthrough` now retains its actual diagnostic instead of being obscured by success-evidence decoding. Successful binding evidence remains strict and unchanged: an ordinary status response or a failed control request never authorizes migration or proves a fresh confirmed binding. No Tern reconnect success is claimed.

When an executable update is unsupported or unavailable, the native card offers the validated release's official installation-instructions page instead of an unexplained archive download. The fallback and retain-existing-settings/characters guidance are localized in Korean, English, Japanese and Simplified Chinese (`KO`, `EN`, `JA`, `zh-Hans`). Release metadata and destination trust checks remain enforced; this link is guidance, not an automatic installation or profile migration.

## Distribution and unchanged contracts

The neutral app, Core and paired coordinator use `0.4.13-beta.10`. Protocol 4, observation 2, integration API 1, migration handover protocol 1, shared contracts `0.1.0`, legacy bridge identity `0.3.16` and adapter pins are unchanged. The beta.9 rig CPU and hidden-rendering corrections remain included; their [beta.9 evidence and limitations](v0.4.13-beta.9.md) are not relabeled beta.10 verification. Stable latest and migration remain `0.4.12`.

Standalone installation retains the actual OS account home's `.local/share/desktop-pet/libexec/DesktopPet.app`; Homebrew and source retain their existing owners. **The new ordinary installer does not relocate an old Applications installation.** It does not adopt that owner, repair an installed application or reconnect Tern. The personal Python recovery script remains withdrawn and is not shipped in this release or its checksums; do not use an old withdrawn copy. Private one-time recovery remains separate from product distribution. Existing profiles, settings, characters and running Tern work must be preserved.

The exact [beta.10 prerelease page](https://github.com/hanbong5938/desktop-pet/releases/tag/v0.4.13-beta.10) is the intended publication endpoint, never stable latest; this link is not a claim that publication has occurred. Publication is authorized only as a **non-latest prerelease**, with `prerelease=true`, `make_latest=false` and no overwrite of old tags/assets. Its six asset names are:

1. `DesktopPet-v0.4.13-beta.10-macos-arm64.tar.gz`
2. `DesktopPet-v0.4.13-beta.10-macos-arm64.tar.gz.sha256`
3. `SHA256SUMS`
4. `DesktopPet-v0.4.13-beta.10-rig-native.json`
5. `desktop-pet-install-v0.4.13-beta.10.sh`
6. `desktop-pet-install-v0.4.13-beta.10.sh.sha256`

Verify the archive and installer against their individual checksums, all three payloads against `SHA256SUMS`, then the exact signed deployed resource closure against the external rig sidecar. The archive contains only `DesktopPet.app`. Signing is local **ad-hoc, not Developer ID or notarization**. Publishing and downloading do not install, relocate or restart an existing user app. Save Pet edits before any separately consented update and retain the established owner/profile admission policy.
