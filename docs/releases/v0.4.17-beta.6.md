# Desktop Pet v0.4.17-beta.6 release notes

## Recovery admission and protected Pet-only restart

This testing-only prerelease follows [beta.5](v0.4.17-beta.5.md) and merges the recovery corrections with current mainline authority and preference-ownership fixes. Stable v0.4.16 remains latest. Existing tags and assets are immutable; no stable formula or installed-user/mini cutover is included.

- Enable the exact authenticated recovery action even when unresolved history makes the card look busy. After verified reconciliation, allow manual Check while keeping policy switches protected. Migration, relocation, active workers, stale contexts and uncertain journals remain fenced.
- Replace legacy recovery's public CLI Stop with one request bound to the authenticated original peer. Require the exact shutdown ACK and one generation increment. Lost or invalid acknowledgement never causes a retry, helper handoff or automatic start.
- Recognize an already-approved fresh Original when re-entering NoSpawn recovery after interruption. Require fresh complete reservation markers and the exact durable startup origin; preserve Failed / installed=false / applied=false rather than claiming an update. Do not replay a manager or revive a later-stopped app.
- Run Reset all settings confirmation outside the UI RefCell borrow so ordinary Stop can abort the open modal. Revalidate the exact profile/context, captured Stop generation and current unsaved-edit/IME/migration/shutdown blockers after approval. Cancel changes nothing.
- Route UI Restart through an exact-source protected shutdown handoff rather than public CLI restart. Freeze input before returning from approval, remove inherited startup authorization, authenticate one Stop and fence the replacement at its exact successor generation. Preserve the same profile, live observation selection, invocation assets and integration routing.
- Keep reset/restart handoffs locked on uncertain child wait/disconnect or denied exact-source release. Reporter threads own child creation and reaping; native/AX composer, dialogue and palette ingress remain protected while read-only navigation and ordinary Stop/Quit remain available.
- Synchronize the full existing settings state when only the Appearance detail window is visible. External passthrough changes and rejected-action rollback must agree with the controls without replacing active drafts, marked text or selection.
- Retain mainline source-replacement receipt, manager-quiescence, preference-owner publication and authenticated delivery guards. A staged or uncertain replacement is not a completed installation.

## Verification and limits

Before release preparation, both neutral and legacy workspace gates and actual main-thread production AppKit regressions passed on the correction branch. A newly packaged ad-hoc-signed isolated app exercised the actual native Reset button and approval modal followed by the actual Restart button: fresh ready instances used the same profile and generation advanced 0 → 1 → 2. The exact settings backup, 41 imported-pack file hashes, lifecycle/routing bytes and assets selection were preserved. A separate private-command scenario verified stale inherited manual authorization; wrong source instance/generation failed before Stop without changing the live source or configuration.

Debugger/OS barriers exercised additional ordinary Stop immediately before the bound request, after verified ACK while the source was shutting down, and with the replacement daemon pending before control readiness. All workers exited nonzero, final running=false, and no new ready instance appeared. The last case completed only after the existing startup deadline; this is not an immediate-exit claim. Disposable profiles/processes were stopped and removed. Final merged-source gates and the exact-tag workflow qualify the release candidate separately; earlier correction-branch evidence is not substituted for downloaded-release identity/readiness proof.

The final merged candidate passed neutral and legacy workspace gates, the real main-thread recovery UI executable in both distributions, all eight Core/Herdr composition regressions, TypeScript checking, 68 script/rig tests and the deformation gate. The published immutable adapter pins were used without local path patches. During integration, one rollback fixture returned bare OS EINVAL; stage/syscall diagnostics were added and the focused scenario plus final full gates passed, but the earlier intermittent cause remains unestablished.

**Not certified:** genuine signed coordinator NoSpawn crash-boundary and retained legacy-helper/ACK-loss end-to-end transactions are `[blocked: isolated account unavailable]`. Temp-global reservation and authenticated peer regressions cover deterministic boundaries but do not replace a disposable-account crash proof. The Aqua session was locked: local native actions/state assertions do not certify physical keyboard, IME, focus or VoiceOver; a cached bitmap with rendering artifacts is not clean visual acceptance.

Older installed executables do not acquire these fixes retroactively. Preserve original helpers, journals and reservations; Unknown is not permission to retry Stop or replay installation. Resetting preferences is not updater recovery. Beta2 still lacks the independent manual-start fence required for safe in-coordinator Start after retained-helper cleanup.

Contracts 0.1.0, legacy 0.3.16, updater protocol 4, observation 2, integration API 1, migration handover 1 and `MIGRATION_TARGET_VERSION=0.4.12` remain unchanged. Herdr is pinned to published revision `0b9e24b2f6498311229a328ad144a4ab41b7505b` for mainline's preference-owner/deadline integration and composition test support. Tern's adapter and bundled consumer share the compatible merged revision `bb10061fd9cd8813bf425fde409c62f145f2b895`; all 44 adapter regressions passed against the target Core contracts, and plugin/window/license bytes are unchanged from beta.5's authority branch. These source pins do not publish a host integration release, install a plugin or change the separately authenticated Herdr migration revision. The exact-tag workflow prepares six immutable prerelease assets for downloaded-asset qualification before publication. Packages are ad-hoc signed, not Developer ID signed or notarized.

## 한국어

- 실패 이력 때문에 필요한 복구 버튼이 비활성화되거나 정리 후 수동 확인까지 막히는 문제를 수정했습니다. 실제 진행·예약·불명 상태의 보호는 유지합니다.
- 구형 복구의 Stop을 원본 peer에 묶인 한 번의 요청으로 바꾸고 정확한 ACK와 generation +1을 요구합니다. 응답이 불명확하면 재전송·도우미 실행·시작하지 않습니다.
- NoSpawn 복구 중 이미 승인되어 준비된 새 원본을 재진입 시 인정하되, 실패 이력을 업데이트 성공으로 바꾸거나 manager를 다시 실행하지 않습니다.
- 초기화 확인창이 열린 동안 Stop 콜백이 실행될 수 있도록 UI borrow를 해제하고, 승인 후 원래 context·Stop generation·초안/IME 상태를 다시 확인합니다.
- UI 재시작은 입력을 먼저 잠근 뒤 정확한 원본만 종료·재시작합니다. 오래된 startup 환경을 제거하며 추가 사용자 Stop이 부활보다 우선합니다. worker 종료가 불확실하면 잠금을 풀지 않습니다.
- 작은 패널이 숨겨진 외형 상세창도 외부 설정 변경과 전체 상태를 동기화하고 현재 초안·조합·선택은 보존합니다.

격리된 실제 앱의 Reset → Restart 및 Stop 경합을 검증했습니다. 별도 계정/VM이 필요한 실제 coordinator 중단 복구와 옛 retained-helper ACK 유실 거래는 미검증으로 남깁니다. 사용자 기본/mini 설치·프로필과 Tern은 변경하지 않았으며, 안정판 latest는 v0.4.16을 유지합니다.
