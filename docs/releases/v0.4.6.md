## Installation census: negative scope only

When macOS cannot supply a live process's `proc_pidpath`, the shared installation scanner uses validated executable-derived kernel `comm` only to exclude a clearly unrelated process. Empty or malformed metadata, pet executable names and truncated-prefix collisions remain fail-closed. Only a proven zombie or `ESRCH` proves inactivity. Command-line text, mutable process names and UID filtering do not establish authority.

An explicitly authorized PID still requires its exact live executable path and hash. A genuine authentication failure still reports `cannot authenticate live process image PID`, now with the captured path error. This repair removes unrelated-process false positives without admitting an unauthenticated pet process or treating a missing executable path as proof that an owned installation is stopped.

## Authenticated live-host buffer-then-close repair

The genuine bridge's live Herdr query now reads a complete buffered response even when the authenticated peer closes immediately after writing it and readiness includes a hangup. Nonblocking I/O and polling share one absolute deadline; the reader drains the buffered frame rather than attempting to install a receive timeout on an already closed peer. EOF before a complete frame, timeout, oversized or malformed replies, unrelated response IDs and missing/invalid snapshot fields remain errors.

Peer UID, kernel peer PID and executable authentication remain mandatory. The connected process's live version, not a newer disk CLI, must satisfy the host requirement. The formerly failing `origin::tests::prospective_host_requirement_uses_connected_process_version_not_disk_binary` now passes in the working successor coordinator gate. This is a production transport correction, not a suppressed test failure or a substitute for a genuine installed host/runtime exercise.
