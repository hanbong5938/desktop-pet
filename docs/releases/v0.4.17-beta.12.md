# Desktop Pet v0.4.17-beta.12 release notes

Testing-only prerelease. Stable/default channels and automatic beta preferences remain unchanged.

## Complete Tern transport and delivery cutover

Regular Tern exchange now uses authenticated loopback `tern.fetch` instead of the per-poll `tern.process.run` launch that was observed pending when Tern 0.9.5's callback watchdog fired. The bounded private endpoint binds the original profile and live instance; proxy ambiguity, origins, host/framing errors, duplicate JSON keys and stale profile/endpoint replies fail closed. Existing command, snapshot and receipt semantics remain; there is no subprocess exchange fallback. Signed setup and approved handover subprocesses remain.

The signed delivery manifest, all three downloaded file digests and compiled adapter now pin the same consumer **v0.2.2-beta.3** revision, `0d505377cb682fdcca4735438b184d72f65e43fa`. Production window bytes remain the qualified `d9499f1c607a8a6766f65c0916cebd5a9126d7fd` implementation; subsequent consumer commits only correct paired release guidance. Native package admission recognizes the current beta.3 package and retained beta.2 evidence without allowing either version to substitute the exact captured package digest/revision. Unknown versions remain rejected.

Earlier beta.10/.11 annotated source tags remain immutable and have no published app artifacts. The beta.10 workflow was cancelled; beta.11 passed its workspace/tooling gates but packaging correctly rejected the stale beta.2 delivery pin. This successor fixes that pin and native package admission rather than weakening checksum or signed-source gates.

## Preserve canonical installation history

For an already-canonical, normally stopped source, `install-manual-recovery --request ABS` accepts only an explicitly approved version-3 request with `confirmation:"replace_canonical_app_preserve_profile_allow_beta"`, targeting a strictly newer independently signed official beta. It uses the existing retained same-root atomic exchange and records the new image in a new immutable operation. Existing stable-only v1 H → C and beta-only v2 H → C remain separate authorizations.

The original owner/profile, settings, characters, signed original bundle and historical records remain retained. No native confirmation panel, synthesized Stop ACK, updater parent or restart token is created. An unchanged Stop generation is required; success remains `installed_stopped`, `applied:false`, `restart:"not_requested"`. A separately approved normal Start follows verified reservation release. C → C does not rewrite the saved Tern route. Do not raw-install over an installed-only operation, delete its records, reset profiles or restart Tern to conceal a mismatch. See the [CLI contract](../cli.md) and [canonical recovery design](v0.4.17-beta.11.md).

## Verification boundaries

The canonical recovery source passed 349 coordinator regressions and a compiled-CLI wrong-owner rejection smoke before this packaging successor. Its full workspace/tooling gate also passed in beta.11 CI. The transport source passed native core tests (733 passed, 1 ignored), composition checks, TypeScript and 68 Bun checks. Consumer production source passed 272/272 controlled-boundary regressions in the actual isolated Tern 0.9.5 Luau VM; a separate real-SDK HTTP smoke completed 32 authenticated sequential requests.

The new consumer-admission regression checks exact digest authority across current/retained versions and rejects an unknown successor. Release packaging, signed closure/digests and deployed-byte runtime behavior require their own qualification. Controlled tests/builds do not prove actual user-session continuity, agent/model delivery or physical GUI acceptance. No computer-use automation is part of this recovery.
