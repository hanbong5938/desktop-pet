# Desktop Pet v0.4.17-beta.2 release notes

## Simpler settings, retained native details

This testing-only prerelease adds the settings simplification to v0.4.17-beta.1. Stable v0.4.16 remains latest; this beta is not a stable promotion.

- The basic panel has three tabs: **Appearance / Connections / App**. Common settings and short status summaries stay in the compact panel.
- Six direct buttons open one retained, nonmodal detail window: Appearance Details, Connection Settings, Menu Bar Settings, Update Settings, Connection Diagnostics and Update Details. Long paths, raw errors, provider controls, color fields, update history and diagnostics no longer occupy the basic documents.
- Color drafts and conflict handling use the existing preference model. Viewing or closing details is not a save, and update, migration and relocation approvals remain separate.
- Detail-window Cmd-A/C/X/V/Z and Cmd-Shift-Z go to the actual focused editor, including selectable readonly diagnostics. Frozen and readonly mutation shortcuts are consumed without invoking editor actions or Undo.
- Freeze leaves scroll navigation available and preserves the actual active color editor, UTF-16 selection and native Undo/Redo history. Its private field reports disabled without the AppKit setter that terminates editing; inactive controls retain their enabled-state snapshot and restore behavior.

## Verification and known limits

Before the version cutover, the same disposable main-thread production-view fixture reproduced 22 failures in 48 proof rows on the original settings source, then passed all 48 on the corrected source. It exercised both native key-dispatch paths, real native insertion and Undo/Redo, refresh/rebase/freeze/thaw continuity, frozen selection reentry and clicking, readonly copying, current disabled eligibility and Legacy/Overlay thumb dragging through 120-row diagnostics. The fixture and its temporary bridges are not shipped in the product.

That settings-source validation also passed core/workspace Cargo gates, TypeScript checking, a neutral release build and ad-hoc packaging. A separately packaged isolated profile exercised start/status/settings and external theme/language commits, then only that profile was stopped. These observations precede this beta's version cutover; final beta-source gates, exact tagged CI and independent asset qualification are separate evidence, not inferred from the earlier results.

After the beta.2 version cutover and Rust formatting, the production-view fixture was rerun and passed all 48 rows. The final local workspace Cargo gate passed (one ignored test), as did `bun run check`, the 62-test release/Wiki/rig JavaScript suite, `cargo fmt --check`, release-note metadata/link validation and the native rig deformation scenario. The Git-heavy malformed-link Wiki fixture exceeded Bun's default five-second deadline during the first run; its explicit bounded deadline is now 30 seconds, with all link-rejection and unchanged-output assertions retained. The complete suite then passed. Exact tagged CI, the newly built release bytes and asset publication still require their own observed qualification.

**Actual GUI acceptance remains incomplete:** the macOS session was locked with loginwindow frontmost, so no global input was sent. All eight real-app scenarios remain blocked: three-tab information density, six direct opener/window-lifetime interactions, draft/selection/Undo across topic and close/reopen, external draft conflicts and actual Korean/Japanese IME, icon-picker Cancel/valid/invalid PNG persistence, long diagnostics/copy/locale, detail-only refresh and real mutation rejection, and keyboard/small-screen/VoiceOver acceptance. Some locked-session cached-view images have rendering artifacts; they are not clean visual acceptance. Native fixture measurements do not replace these real-app checks.

See the [settings correction evidence and individual blocked rows](unreleased.md#focused-editing-and-frozen-navigation-correction) and [usage guide](../usage.md).

## Preservation and compatibility

The v0.4.16 recovery fixes carried by beta.1 remain included. This settings change does not add installation, profile adoption, update or migration authority. Original settings, characters, config/state, retained recovery evidence and unrelated profiles remain authoritative. No Tern restart, plugin reload, host reinstall or consumer-route rewrite is introduced.

Storage schemas and CLI wire contracts are unchanged. Legacy migration authority remains `MIGRATION_TARGET_VERSION=0.4.12`; legacy `0.3.16`, contracts `0.1.0`, protocol 4, observation 2, integration API 1, migration handover protocol 1 and the adapter/consumer pins remain unchanged. Homebrew formulae and the stable release are not changed by this prerelease.

## Publication boundary

The exact-tag workflow prepares a draft `v0.4.17-beta.2` prerelease with asset overwriting disabled. Publication follows qualification of its six app/installer assets and remains non-latest. Existing published tags, release bodies, assets and checksums stay immutable.

The package is **ad-hoc signed, not Developer ID signed or notarized**. Publication and source/native-view checks do not establish a successful live installation, existing-user update/recovery, actual Stop/restart or Tern connection continuity. No installed user app or default profile was replaced during the settings-source validation.

## 한국어

설정 기본 화면을 **꾸미기 / 연결 / 앱 설정** 3탭으로 정리하고, 긴 설명·색상 편집·제공자 설정·진단·업데이트 이력은 하나의 유지되는 비모달 상세창으로 옮긴 테스트용 베타입니다. 편집 단축키를 실제 포커스된 편집기로 전달하며, 업데이트 freeze 중에도 진단 스크롤·복사를 유지하고 색상 편집기의 선택·native Undo/Redo를 보존합니다. 상세창 열기·닫기는 저장이 아니며 기존 초안·충돌 처리와 별도 업데이트/이관 승인 규칙을 유지합니다.
