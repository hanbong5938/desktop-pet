# Desktop Pet v0.4.14 release notes

## Correct one-shot macOS control-peer authentication

The coordinator previously queried Darwin `LOCAL_PEERPID` again after receiving a complete reply. The native control server closes each one-shot connection after replying; Darwin then returns `ENOTCONN` even while the authenticated app is still running. The helper consequently failed before installation with `cannot authenticate control peer PID`.

The correction keeps the mandatory socket UID and kernel PID authentication before sending any request. After the reply it recaptures that same kernel-authenticated process and compares its complete UID, incarnation, executable vnode and path evidence. It does not trust a PID supplied by JSON, weaken authentication to UID-only, reconnect, replay requests or suppress errors. Stop/restart, reservation and approval rules are unchanged.

Read-only investigation reproduced the closed-socket failure on the affected Mac while the original beta.7 process remained ready. A deterministic real-AF_UNIX regression exercises immediate-close replies. The installed immutable beta.7 helper still contains the defect; merely publishing this patch cannot repair that helper. The affected owner explicitly approved a scoped SSH recovery, original/profile retention and Pet-only normal shutdown/restart. Actual recovery must be reported separately from source or release verification.

Original config/state, characters, settings and work must be preserved. Native publication, native readiness and actual Tern window/work continuity remain distinct observations. Existing signed tags and assets, including v0.4.13, remain immutable. Independent legacy migration authority stays at 0.4.12; legacy0.3.16, contracts0.1.0 and protocol/consumer pins are unchanged. Homebrew formulae are unchanged.

## Explicitly approved stopped-source recovery

The separate `install-manual-recovery` operator command requires an already-stopped original Applications owner, a strictly newer compiled Stable candidate with retained official archive/checksum evidence, and the exact original profile. It reuses the two-root reservation and atomic relocation commit/retention transaction with independent source/candidate closures. A distinct immutable `ssh_operator` receipt binds actual plan/request bytes; it is not a native-panel consent, settled updater parent or Stop ACK.

The helper neither stops nor restarts Pet and reports `installed_stopped`, `applied:false`, `restart:"not_requested"`. A separately approved normal start occurs only after verified reservation release. Tern's unchanged consumer may then save the executable-only route after authenticating the committed manual operation and a fresh ready private instance. Installation alone is not connection proof.

RuntimeStart v2 records the real daemon's captured startup context and existing generation/root/process identity. Manual cold reconstruction authenticates the initial context even when a later restart or updater uses different settings. Older v1 receipts remain readable as fence facts, not invented context evidence. Current-instance readiness and the latest Stop generation remain mandatory; no old outcome is rewritten as applied.
