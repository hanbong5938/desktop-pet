# Desktop Pet v0.4.13-beta.8 release notes

Status: **Testing-only corrective beta candidate; qualification and publication pending integration-owner proof.** This source follows published beta.7 without rewriting its immutable tag, installer, assets or [frozen release notes](v0.4.13-beta.7.md). It does not assert final checks, official CI, public beta.8 assets, canonical UI acceptance or successful recovery on the affected Mac. Stable `0.4.12` remains latest stable and the authorized migration target.

## Private Standalone destination

New Standalone installation uses the **actual OS account home**’s `.local/share/desktop-pet/libexec/DesktopPet.app`, not `Applications/DesktopPet.app` and not an arbitrary `HOME`/XDG override. Homebrew still owns its verified formula prefix’s `libexec/DesktopPet.app`; an admitted source installation still uses the exact core checkout’s `dist/DesktopPet.app`. Use the verified installer-reported executable and exact existing config/state pair rather than guessing a path.

This correction does not silently relocate or adopt an existing Applications owner. **Rerunning an immutable beta.7 or older pinned installer cannot repair its destination.** Historical path descriptions retain their original release scope; no prior release bytes or provenance are rewritten.

## Separate one-time recovery artifact

The mistaken Applications installation is addressed by an explicitly run **standard-library Python 3 script**, source `scripts/repair-applications-install.py`, distributed separately as `desktop-pet-repair-applications-v0.4.13-beta.8.py`. It is **not part of the installed native runtime**, a new Rust repair/route feature, a plugin update or a generic repair framework. No new product repair API, protocol or schema is introduced.

The script defaults to **dry-run**. Mutation requires `--apply`; a manual restart additionally requires `--start`. Optional `--tern-kv ABS` selects a custom saved SDK file; optional `--config-dir ABS --state-dir ABS` must be supplied together and match both saved connection paths exactly. See [current recovery guidance](../usage.md#one-time-applications-recovery-beta8-candidate) for commands, environment limitations and failure handling.

Runtime requirement is Python **3.9+**, standard library only. Explicit `--dry-run` is also accepted and is mutually exclusive with `--apply`. After a requested Start, native readiness without confirmed fresh Tern binding is reported separately with exit **3**, not as completed recovery. Repeating a completed repair never replays Start; a repeated `--start` prints the exact separate Start command and exits **3** because that invocation did not verify reconnection. If an earlier mistaken no-argument launch created a neutral-default daemon, stopping it additionally requires exact kernel argv/profile and authenticated PID/image proof; back up its data and never restart it as the original profile. Original assets inside the old bundle that must be moved cause pre-Stop refusal rather than a guessed assets replacement.

- Derive the original profile from the exact saved Tern KV connection, **never from a no-argument app launch**, guessed neutral defaults, profile adoption or a hardcoded example pair. The saved executable must match the old Applications installation. Brew/source/custom routes, conflicting destinations, unsafe ownership or symlinks are rejected.
- Fetch the fixed official beta.8 archive, sidecar and checksums and validate the complete signed deployed closure before any Stop. There is no mutable latest/source fallback. The script independently verifies the candidate and uses its paired helper’s `install --request` primitive; it does not run a downloaded shell installer.
- Back up the full old bundle and original sidecar, matching locator, original KV bytes and profile data under the actual home’s `.local/share/desktop-pet/repair-backups`, with a durable manifest/phase. Preserve original profile data, unrelated KV fields and default-profile selection. Leave no Applications symlink or launcher.
- Save unsaved Pet drafts first. Apply may request ordinary **Pet-only Stop** on a proven exact profile and must refuse unknown/conflicting profiles instead of killing them. It does not terminate/restart Tern, windows, terminals or agent work, change plugin code/catalog, force reload or require Configure/Connect. Do not change plugin settings or run another installer/updater during apply.
- Verify the private owner/image/locator before atomically changing only the matching saved connection executable. Back up the original bytes and reject observed concurrent changes. Tern’s documented [KV reread behavior](https://docs.stencil.so/tern/reference/api-shared.md#ternkv) is the route-update mechanism, not proof that actual reconnection has succeeded.
- Without `--start`, remain stopped. Explicit `--start` has normal manual Start semantics, uses the saved exact pair and available authenticated original observation/assets context, and checks for an additional observed Stop. It is not native updater reservation authority or a claim of race-proof transactional restart. Missing source-specific environment cannot be reconstructed by guesses; use the actual Tern environment for custom routing.
- Report verified installation separately from runtime readiness and actual Tern reconnection. On uncertain failure, preserve backups and report exact old/new/backup paths; do not blindly overwrite changed paths/KV, restart or claim success. Recognize a completed same-beta private repair without repeating Stop/install.

The existing Pet-only coordinated updater and its separate Stop/reservation/recovery boundaries are not replaced by this manual script. Ordinary installation does not gain authority to rewrite plugin routes. The script’s narrowly requested executable correction is not migration receipt/handover authority.

## Evidence and pending gates

Observed local beta.8-source checks: TypeScript passed; **65 Bun tests / 767 expectations** passed; **19 Python recovery regressions** passed; the native workspace passed, including **174 coordinator library tests**, **29 helper tests**, and **657 Core tests passed / 1 ignored**. Rust formatting, shell syntax and exact-tag release-note/metadata admission passed. The script's actual `--help` entrypoint ran. Its signature/closure/paired-owner inspection and private-socket PID/image/profile authentication were also exercised read-only against the development account's real signed **0.4.12** standalone bundle (**72 deployed files**); no Stop, move, KV change or repair was applied. That source inspection is not beta.1 or affected-Mac recovery proof.

The first local native gate exposed a completion-marker race in `detached_worker_survives_owning_parent_exit`: the parent observed the marker after shell redirection created it but before `printf` wrote `finished`. The fixture now writes a private sibling marker then atomically renames it into place. The targeted regression and full native workspace passed after this fixture-only correction; production process, Stop and readiness checks were not weakened.

No beta.8 archive/script digest, final tagged build identity, official CI, publication or user-machine result is asserted before it is observed. Signed candidate staging and independent public-byte validation remain separate gates. Prior beta.7/component results cannot be relabeled beta.8 proof.

**Canonical installation, physical native UI, original-profile restart, real same-window Tern reconnection with ongoing terminal/agent work and full affected-machine recovery remain unverified.** An owned isolated OS account/VM is required; a fake `HOME`, fixture, successful copy, source dry-run or connection count alone cannot close that gate. Do not bypass ownership, signature, exact-profile, concurrent-edit or Stop checks to turn uncertainty into success.

## 한국어 요약

- beta.8은 Standalone 새 설치 목적지를 실제 OS home의 `.local/share/desktop-pet/libexec/DesktopPet.app`으로 수정하는 **테스트 전용 후보**입니다. Brew/source 소유권은 유지하며 공개 beta.7 자산·태그·설치기·노트는 바꾸지 않습니다. 옛 설치기를 다시 실행해도 잘못된 Applications 목적지는 복구되지 않습니다.
- 일회성 복구는 앱에 넣는 Rust 기능이 아니라 별도 Python 3 자산 `desktop-pet-repair-applications-v0.4.13-beta.8.py`입니다. checksum 확인 후 기본 dry-run부터 실행하고, 명시적 `--apply`만 변경하며 `--apply --start`만 수동 시작을 요청합니다. 원래 프로필은 저장된 Tern KV의 정확한 config/state 쌍에서 읽습니다. 인자 없는 실행·기본 프로필 추측·병합·adopt를 사용하지 않습니다.
- Pet 편집을 먼저 저장하고 적용 중 플러그인 설정을 바꾸지 마세요. 원본 앱/sidecar·locator·KV·프로필을 private backup에 보존하고, 새 설치 검증 후 일치하는 KV 실행 파일 필드만 바꿉니다. Tern·창·터미널·agent 종료/재시작이나 reload/Configure/Connect를 요구하지 않습니다. `--start` 없이는 stopped이며 추가 Stop와 불확실성에서는 재시작하지 않습니다.
- 위 여덟 자산은 게시 계약이지 게시 완료 주장이 아닙니다. 최종 검사·CI·공개 bytes와 canonical UI·실제 원래 프로필/Tern 재연결 수락은 통합 소유자의 관측 전 미검증입니다. 설치 완료와 실제 재연결을 구분하며 백업·실패 증거를 보존합니다. 안정판/마이그레이션 대상 `0.4.12`와 beta Download 전용 정책은 유지합니다.
