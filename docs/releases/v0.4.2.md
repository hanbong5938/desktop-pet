# Desktop Pet v0.4.2 release notes

## Publication boundary

The user approved separate **Core v0.4.2 and Herdr integration v0.4.1**, preserving every previously published tag/asset, after the bridge's strict public-tree gate exposed a Herdr publication error. **v0.4.2 is not yet published.** No future release ID, source revision or archive/installer digest is claimed. Valid published Core v0.4.0/v0.4.1 and Tern v0.2.0 remain immutable.

## Problem and correction

Published Herdr integration v0.4.0, source `f65f123e17822ad838dd40a565900aca6347cd97`, release `412221638`, accidentally contained the generated legacy `dist/HerdrDesktopPet.app` tree in Git, despite its GitHub Release having no uploaded native assets. The thin integration filesystem/staging gates omitted `dist`, so they did not prove an integration-only published source closure. This was a publication error, not a user's host or account failure. Actual bridge build [38490571511](https://github.com/hanbong5938/desktop-pet/actions/runs/38490571511) rejected the real immutable public tree before building a bridge. No bridge was published and no legacy formula was changed by that failed run.

The correction removes that generated distribution from Herdr default source and makes both filesystem and tracked/source-tree ownership gates reject native/common product artifacts before publication. Herdr v0.4.0's public tag/body is retained as faulty history, never silently moved or overwritten. A new Herdr v0.4.1 is required for corrected managed migration. Core's immutable managed-retirement validation and bridge build authority cleanly move to that corrected integration ref; no old/new shim or relaxed artifact check is introduced.

Core v0.4.2 remains the one common app/helper implementation. The genuine legacy bridge stays product **0.3.7**, protocol **3** / observation capability **1**, built from the exact newly published Core v0.4.2 source with the actual published Herdr v0.4.1 retirement ref. The neutral pair stays protocol **4** / observation capability **2** / integration API **1**. Integration versions are independent from the product version.
