# Desktop Pet v0.4.13-beta.11 release notes

Testing-only corrective candidate. **Beta.10 did not fix the existing Applications owner**: support for new private installations left the original beta.7 installation stranded. Beta.11 preserves the exact original existing OS-home `Applications/DesktopPet.app` owner and upgrades it **in place**, through the same separately consented signed transaction. It does not relocate that app or rewrite its SDK route. Final qualification, publication and affected-user acceptance are pending; this source note is not evidence of a successful user upgrade.

## Owner and data preservation

Fresh Standalone installations still use the actual OS account home's `.local/share/desktop-pet/libexec/DesktopPet.app`; beta.11 creates no new Applications installation. Only the exact fully validated existing original OS-home `Applications/DesktopPet.app` receives backward-compatible owner admission. Arbitrary home, custom and system Applications paths, symlink bypasses and silent Brew/source takeover remain forbidden. No new protocol or plan fields are introduced.

The executable path, original config/state pair, profile data, characters, locator's executable selection and saved Tern SDK KV remain in place. The transaction retains the signed prior app, its original sidecar and durable replacement evidence. Save unsaved Pet edits before replacement. Native consent remains explicit and separate: version, signed-image, owner, client-contract, reservation and profile guards remain required. User **Stop** wins and prevents restart. The updater does not terminate Tern, its windows, terminals or agents, and does not reload its plugin.

## Explicit bootstrap from beta.7 or another old version

The old beta.7 checker cannot self-modify its published code. One explicit signed-installer bootstrap is necessary; repeatedly checking for updates in beta.7 or rerunning an old installer cannot add beta.11 admission. **Wait until the exact beta.11 prerelease and assets are actually published.** Download the pinned installer and its checksum from the [exact beta.11 prerelease](https://github.com/hanbong5938/desktop-pet/releases/tag/v0.4.13-beta.11), verify them, and only then explicitly run Bash:

```sh
mkdir -p desktop-pet-beta11-bootstrap
cd desktop-pet-beta11-bootstrap
curl --fail --location --output desktop-pet-install-v0.4.13-beta.11.sh https://github.com/hanbong5938/desktop-pet/releases/download/v0.4.13-beta.11/desktop-pet-install-v0.4.13-beta.11.sh
curl --fail --location --output desktop-pet-install-v0.4.13-beta.11.sh.sha256 https://github.com/hanbong5938/desktop-pet/releases/download/v0.4.13-beta.11/desktop-pet-install-v0.4.13-beta.11.sh.sha256
shasum -a 256 -c desktop-pet-install-v0.4.13-beta.11.sh.sha256 && bash ./desktop-pet-install-v0.4.13-beta.11.sh --prebuilt
```

Run the final line only after both downloads succeed; a failed checksum must prevent execution. Do not pipe a download into a shell. The checksum verifies download integrity; the installer must additionally validate the signed app and exact release identity before the separately consented transaction. Signing is ad-hoc, not Developer ID signing or notarization. Do not remove or re-sign the existing app to bypass admission.

Preserve the complete original app/sidecar, backup, original config/state and SDK KV before any change. Do not delete data, merge/adopt profiles, substitute example/default paths, launch the app with no arguments, or use **Configure/Connect** to hide a continuity failure. Installation, original-profile native readiness and actual same-window Tern continuity are distinct acceptance outcomes. If admission fails, retain the diagnostic and backups rather than forcing another owner or reconnecting. No actual beta.7 recovery success is claimed until observed on the affected installation.
