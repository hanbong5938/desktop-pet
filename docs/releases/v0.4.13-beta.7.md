The immutable `v0.4.13-beta.6` tag identifies source `58a55d061ee7a1811c0870d5a1beecd1086c9a2c`. The actual returned error was **not captured**. That workflow produced **no beta.6 package assets or published beta.6 release**. Preserve its tag and notes as historical evidence; do not move the tag or reuse its asset names for corrected bytes.

The fixture used a mismatched instance identity and closed its reply socket immediately. A response-socket lifetime race is **[INFERENCE]**, not an observed diagnosis of the uncaptured CI error. Beta.7 corrects the fixture rather than weakening production checks:

- Reply status uses the matching current-runtime instance identity.
- The fixture serves **two real status connections** and holds each response socket until client EOF, with a bounded three-second wait.
- Before checking historical discovery, the test decodes actual status and asserts PID, instance, image SHA/path and exact profile, running/control-ready status, and **not-ready / not-UI-ready** status, as well as the actual kernel image path.
- The test still requires `latest_for_context` to reject the not-ready runtime and retains the history/evidence invariants. It drops only the incidental error-wording match; it does not replace evidence or behavior assertions with a wording assertion.

No production transport, readiness, identity, migration evidence or Stop authority is weakened by this correction. Prior beta.6 local checks passed, but the official failure **overrides beta.6 release qualification**. Those local results are historical evidence, not a substitute for the failed official run or proof that beta.7 passes. Beta.7 check results must be recorded only after the integration owner observes them; no successful beta.7 checks or final CI results are asserted here.

## Changes retained from beta.6

- Connect the pinned **prebuilt** installer to a separate native `install-coordinated` transaction for a lower-version, same-owner Standalone installation. Download, signatures, digests, complete deployed closure and candidate validation precede any Stop. Absent installation and verified same/higher-version reuse retain their existing behavior. Raw `install --request`, source installation, migration and other installation owners retain their existing boundaries; Homebrew/Source ownership is not taken over.
- Show native consent identifying old/new versions, installation root and exact config/state profile. The consent authorizes a brief **Desktop Pet-only** shutdown and, only when originally running and properly authorized, restart of the same profile. It does not authorize terminating or restarting Tern, its windows, terminals or agent workloads, changing plugin/KV configuration, or forcing a plugin reload. **Save unsaved Pet edits first: the public beta.1 compatibility bootstrap uses normal Quit, not draft-aware Prepare.** Cancel or failure to create the confirmation window occurs before Stop.
- Separate authenticated installation owners from narrowly proven compatible IPC clients. Kernel main-executable device/inode and process incarnation, complete argv and exact profile proof are required; basename, pathname, PID or version alone is not permission. Compatible clients do not gain daemon start, mutation or commit authority. Unknown commands, mutators and unproved relevant processes remain blockers.
- Preserve the full old bundle and its **original sidecar bytes** in private retained storage after atomic replacement so existing proven clients can finish using old resources. This implementation does **not automatically delete retained storage**, even after the initially observed clients exit. Retention is not installation failure; keep the reported paths and durable evidence for recovery.
- Add durable standalone-install approval, Stop ACK, replacement and outcome records, a detached private helper, typed operation observation in the app/CLI and migration-owner inspection, and separate `install-status` / `install-recover` commands. Standalone evidence is not forged into a normal UpdatePlan or migration/handover receipt.

### Exact live-client compatibility boundary

**Only the exact public beta.1 image with its fully validated signed release closure, or a newly validated paired app/helper release advertising `installation_client_contract:1`, receives compatible-client admission.** The known public beta.1 app SHA-256 is `569699e2beceeeb447cc4e7f6707e067d7dd84ce3c4d93a8bf8f97a9d7402612`; this hash alone does not replace full closure validation. Version strings and ad-hoc signatures alone are insufficient. The contract is additive; historical absence remains inspectable but grants no permission. App/helper capability presence and value must agree.

**Beta.2–beta.5 images lacking that contract are not blanket compatible.** They remain subject to strict process admission and can be rejected during preflight without stopping Tern or any app. This is not a claim that every installed beta can now upgrade while live. Public beta.1 → beta.7 is the intended compatibility test path, not an already-proven end-to-end result. The failed beta.6 tag does not add another public historical-image exception.

Two Tern windows sharing **one native profile** are an intended supported case, not two active native profiles. Different active native profiles using one installation are rejected **before any app is stopped**, with the conflicting profiles identified. No host-wide pause/reload ACK or quiet timing assumption is introduced. When stopped clients identify no unique exact existing profile, installation rejects before mutation rather than creating or adopting a profile.

### Stop ACK and restart authority

The bootstrap captures the authenticated original instance/image/profile, restart context and original Stop generation `g` under the existing root/profile reservation. It records StopIntent and sends one direct authenticated normal Stop. Only a complete, matching Stop ACK plus the verified reservation transition to `g + 1` supplies the bootstrap execution baseline. The immutable approval's original `g` is not rewritten.

A generation change by itself, a timeout, partial write, lost/mismatched ACK or unadvanced authoritative reservation index does not prove successful Stop or permit restart. Recovery never resends Stop or invents an ACK. Only the exact durable ACK and already-advanced index permit the specifically bounded marker reconciliation. Any later user Stop wins over candidate restart and original-image restoration. Uncertain finalization, conflicts or disk/runtime outcomes preserve evidence and reservation rather than forcing a process to exit or claiming success.

## Installation outcome and typed recovery

`installed:true` means verified disk installation; it does not mean a running replacement. `applied:true` additionally requires a fresh authenticated candidate instance on the exact profile, observation and assets, with UI/control ready. A profile that was stopped remains stopped (`installed_stopped`, `restart:"not_requested"`). A committed image with unsuccessful or unproved startup remains **installed but not applied**; it is not reported as preserved-original success.

The result includes `version`, `operation_id`, `state_dir`, `status`, `installation`, `installed`, `applied`, `restart`, `retained_bundle` and `error`, with absent optional values represented by `null`. The native helper's private durable-copy ownership ACK is not installation success. `install-coordinated` waits for a terminal outcome: exit 0 only for `reused`, `installed_stopped` or `applied`; exit 2 for `cancelled`; exit 1 otherwise. `install-status` exit 0 means a valid observation, not a successful operation.

Use the reported operation ID/state directory and retained signed helper:

```text
desktop-pet-update-coordinator install-status --state-dir ABS --operation-id ID
desktop-pet-update-coordinator install-recover --state-dir ABS --operation-id ID
```

Do not substitute normal updater `recover --start`, repeated installation/manual Stop, marker deletion or Configure/KV rewriting. Typed observation distinguishes normal updates from standalone installs and preserves their separate settlement/recovery authority. Recovery consent reconciles existing proven authority; it cannot erase a lost ACK, an unadvanced index or a later user Stop. Retain immutable plans, ACKs, replacement records, logs, helpers and old bundle/sidecar resources. See the [CLI transaction contract](../cli.md#pet-only-standalone-installation-transaction-current-source-contract) and [usage guide](../usage.md).
