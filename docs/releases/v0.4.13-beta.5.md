# Desktop Pet v0.4.13-beta.5 release notes

Status: **Beta prerelease candidate — opt-in experimental source delivery, not proven recovery or a new stable release.** This successor retains published [v0.4.13-beta.3](https://github.com/hanbong5938/desktop-pet/releases/tag/v0.4.13-beta.3) and the Tern consumer correction from the immutable, unpublished beta.4 tag. Stable `0.4.12` remains the latest stable release and the authorized migration target. These notes do not assert beta.5 publication or successful recovery.

## Changes

- Preserve beta.3's canonical neutral `v`-prefixed beta discovery and candidate/checksum revalidation, immutable migration-plan authority with separately selected live profile observations, and completed migration history that does not mask current update checks, errors, details, or actions. Earlier beta UI, session-list, settings and explicit beta-consent improvements remain included.
- Inherit beta.4's exact public Tern consumer and native adapter pin [`7276c1b658a1728883d90207119df31bce118170`](https://github.com/hanbong5938/tern-desktop-pet/commit/7276c1b658a1728883d90207119df31bce118170), replacing beta.3's `69696023e00a0fcda8b85b332a075bfa26d6c26d`. Plugin version stays `0.2.1`; packaging still verifies immutable source digests and agreement between consumer, adapter and lockfile pins.
- Only migration-route authority (`resolve_migration` / `legacy-migration-route`) and handover authority (`handover_process` / `migration-integration-handover`) use **60,000 ms**. Ordinary discovery, installation proof, capabilities and profile setup retain **10,000 ms**; normal exchange retains **2,600 ms**. This is not a global timeout increase.
- Harden the coordinator regression boundary, not production transport: the test observation peer stays open until client EOF, and assertions first prove a live status response/current runtime profile before checking authority rejection. Tests check rejected authority behavior rather than pinning incidental error wording. Production code, deadlines and authority checks are unchanged.

Production validation, errors, retry cadence, notification policy, signatures, original approval, exact profile/instance/image identity, Stop fences, fresh same-window binding and native receipt authority are not weakened. A timeout or stale/mismatched handover still fails closed; the correction does not guarantee completion within 60 seconds.

Beta update entries remain **Download, not Apply**. Beta consent does not install or restart the app, grant automatic beta installation, or qualify a legacy migration route. Existing installation-owner and updater-reservation boundaries remain enforced.

## Failed beta.4 CI — preserved history, not publication

The immutable beta.4 tag identifies source `df4b8615d61d7e537ca5614a55069174c3bbee15`. Official [CI run 39188725938](https://github.com/hanbong5938/desktop-pet/actions/runs/39188725938), job `117856587412`, failed at `2026-10-19T02:14:29Z` **before packaging or asset publication**. No beta.4 binaries or release assets were created by that run. Beta.5 is a new successor, not a retry or rewrite of beta.4; the beta.4 tag and notes remain unchanged.

The coordinator library result was **139 passed / 1 failed**. `migration::integrations::tests::runtime_profile_changes_preserve_authority_and_reject_invalid_handover` failed at `migration_integrations.rs:1990`: actual `Some("Invalid argument (os error 22)")`, expected `Some("Tern handover receipt is stale or belongs to another profile/instance/Stop generation")`. TypeScript/Bun **62**, Rust formatting, Core and AppKit gates had passed in that run. Those partial passes do not turn the failed run into release qualification.

An independent Darwin 27 reproduction observed a fixture close/timeout-reset race consistent with that CI `EINVAL`: when a Unix peer sends a JSON fragment followed by LF and closes immediately, resetting `SO_RCVTIMEO` before the second read can fail with error 22 despite buffered LF; holding the peer open avoids it. The exact syscall in the failed CI run was not traced, so this is not an unqualified CI root-cause claim or a production transport fix. Beta.5 makes the regression fixture's peer lifetime deterministic and proves the live observation boundary before testing authority rejection.

## Known limitations and recovery boundary

**Actual final packaged-consumer cold-load and reload, successful automatic handover with a fresh same-window/instance native receipt, original profile preservation through that handover, measured real SDK authority wall times, and 120 seconds of subsequent exchange remain unverified/blocked. External-PC recovery is not established.** Controlled Luau tests, readiness, a plugin listing, or a staged app do not replace these gates.

The available owned VM had **Tern 0.8.3 signed out** and standalone native **0.4.12**, with retained `awaiting_reconnect` state and settled forward delivery of the **old consumer**. That observation is not corrected-consumer handover or signed-in recovery. It does not authorize fabricated approval/receipt evidence, replaying uncertain delivery or forcing another installation-owner path. The affected external PC requires its own actual evidence before recovery can be claimed.

This prerelease delivers a narrowly scoped existing correction for opt-in testing. It does not establish automatic recovery, extend migration authority to beta, or authorize bypassing validation, Stop, owner admission, fresh binding or native receipt requirements.
