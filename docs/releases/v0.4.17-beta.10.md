# Desktop Pet v0.4.17-beta.10 release notes

## Asynchronous Tern exchange without periodic process launch

This testing-only prerelease follows [beta.9](v0.4.17-beta.9.md). Stable v0.4.16 remains latest. Existing public tags, assets and historical update evidence are not replaced; installing this beta does not enable automatic beta updates.

A bounded trace in an actual Tern 0.9.5 window identified an unfinished `tern.process.run` boundary when the regular exchange callback exceeded Tern's 50 ms watchdog. Approximately 371 ms elapsed between that call's entry and the warning. This attributes the failing boundary, not whether native spawning, blocking or descheduling consumed that interval. Changing zero-delay yields alone was not supported by the isolated SDK probe.

- Replace regular window exchange subprocesses with documented asynchronous `tern.fetch`. Signed installation/profile discovery, approved saved-route repair and handover commands remain; failed exchange never falls back to polling through `tern-exchange`.
- Native core owns a provider-neutral HTTP listener for registered extensions only. It binds numeric `127.0.0.1` on an ephemeral port and publishes private, atomic, bounded `extension-http.json` discovery for the exact daemon instance and selected config/state pair. Each lifetime gets a cryptographically random 256-bit bearer. Bare compositions without extensions create no listener or descriptor.
- Reject missing/wrong authentication, browser Origin, unexpected Host/path/method, malformed or duplicate headers, transfer encodings, oversized input, recursive duplicate JSON and non-extension commands before dispatch. Existing per-extension request/response limits, preference gates and domain handlers remain authoritative. HTTP has eight independent bounded client slots, so unauthenticated TCP saturation cannot consume the private Unix control budget. Absolute I/O deadlines and lifecycle cleanup bound stalled connections; a retired token cannot authorize a replacement daemon.
- Consumer validation checks the exact six-field descriptor schema, 4096-byte read limit, selected profile, instance, numeric loopback URL and bearer shape. Descriptor bytes are rechecked before POST, response admission and final semantic delivery. The saved route is checked after the final descriptor read, so that read cannot let an obsolete profile deliver an ask.
- Preserve wire v2, per-window epochs/sequences, host generations, source retirement, uncertain receipt handling and local-only semantic asks. Restarted/changed endpoints establish fresh result-free bindings; old callbacks cannot replay an ask or clear newer work. The public `tern-exchange` CLI remains a real diagnostic interface.
- Tern fetch inherits proxy environment. If any HTTP/HTTPS/ALL proxy variable is set, every present `NO_PROXY`/`no_proxy` value must explicitly include `127.0.0.1` or `*`; missing/conflicting exemptions fail closed before sending private bearer or observations. SDK transport diagnostics and bodies are not echoed into errors.

## Paired consumer and installation

The bundled Tern plugin is **0.2.2-beta.3**, immutable revision `d9499f1c607a8a6766f65c0916cebd5a9126d7fd`. It requires this native HTTP descriptor v1 contract in addition to integration API 1; older app versions do not provide it. Install the verified beta app, then its signed consumer package:

```sh
tern plugin install "$HOME/.local/share/desktop-pet/libexec/DesktopPet.app/Contents/Resources/integrations/tern-desktop-pet" --force
```

This supported CLI delivery reloads plugin VMs while preserving their separate KV and does not restart Tern or its sessions. Reload is delivery of the new implementation, not a periodic watchdog workaround. Neither a successful install command nor a Ready plugin catalog proves live reconnection; verify native sources and live sessions separately. The consumer does not install, start or stop native.

For an already canonical standalone owner, the signed helper's existing raw `install --request ABS` admission supports an explicitly requested replacement only after affected installations/profiles are inactive. A strict v1 request selects `kind:"standalone"` and the complete validated `staged_app`; same-owner, signed-resource, version, live-client and reservation fences remain. Back up the complete original bundle/sidecar and profile, stop only Pet normally, replace through that helper, then separately Start the same profile. Do not copy over a running app, fabricate native consent, delete reservations/history, or stop Tern. Historical Applications-owner recovery remains beta.9's separate explicitly approved path.

## Verification and compatibility

Before publication, the native core suite passed **733 tests**, with one ignored test. New real-socket regressions cover authentication/framing/duplicate JSON, exact byte limits, Unix dispatch preservation, idle HTTP saturation, timeout/no-late-mutation, token rotation, descriptor ownership, publication failure and bare-core startup. The unchanged production consumer source passed **272/272** controlled-boundary cases in Tern 0.9.5's actual isolated Luau VM. The final descriptor-read/profile-change race was reproduced failing before its ordering correction and passed afterward. A separate real-SDK HTTP smoke completed 32 authenticated sequential requests; maximum observed fetch registration was 0.922 ms in that sample, not a latency guarantee or live-session soak result.

The exact-tag release workflow additionally gates the locked workspace and composition, TypeScript/release/rig tooling, formatting and signed arm64 packaging. Downloaded draft artifacts require checksum, native identity, signature, signed-resource closure and bundled-consumer qualification before public release. Post-install source/session continuity and restart recovery require separate local runtime evidence. No screenshot, Accessibility, input injection, native confirmation-window automation or physical GUI acceptance is claimed.

Herdr remains pinned to `0b9e24b2f6498311229a328ad144a4ab41b7505b`. Contracts 0.1.0, legacy 0.3.16, updater protocol 4, observation 2, integration API 1, migration handover 1 and `MIGRATION_TARGET_VERSION=0.4.12` are unchanged.

## 한국어

- 실제 Tern 0.9.5에서 주기적인 프로세스 실행 경계가 50ms 콜백 제한을 넘는 것을 확인했습니다. 단순 지연 변경이나 반복 reload 대신 일반 교환을 인증된 비동기 로컬 HTTP로 전환합니다.
- 선택한 프로필·데몬 인스턴스·일회 수명 토큰을 결합하고 외부 주소·브라우저 요청·잘못된 인증·중복 JSON·과도한 요청을 차단합니다. 인증 전 HTTP 연결이 기존 Unix 제어 연결의 자리를 소진하지 않습니다.
- 재시작·프로필 변경 때 미확정 작업을 폐기하며 오래된 질문을 다시 보내지 않습니다. 최종 descriptor 파일 읽기 뒤에도 저장 경로를 검사합니다. 로컬/원격 관찰과 로컬 전용 질문 규칙은 유지합니다.
- 플러그인 beta.3과 앱 beta.10을 함께 사용해야 합니다. 프록시가 있으면 `NO_PROXY`/`no_proxy`에 `127.0.0.1` 또는 `*` 예외가 필요하며 그렇지 않으면 민감한 정보를 보내지 않습니다.
- CLI로 서명된 소비자를 교체하며 Tern과 기존 세션은 종료하지 않습니다. 앱 설치·플러그인 Ready와 실제 연결 유지는 별도로 검증합니다. 기존 설정·캐릭터·업데이트 기록은 보존합니다.
