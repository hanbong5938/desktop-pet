# Desktop Pet v0.4.13-beta.2 release notes

Status: **Beta prerelease — opt-in testing, not a new stable release.** This expanded-bubble layout and session-count clarification follows [v0.4.13-beta.1](https://github.com/hanbong5938/desktop-pet/releases/tag/v0.4.13-beta.1). Beta software may be unstable or contain bugs. Stable v0.4.12 remains the latest stable release; this prerelease does not change stable installer pointers, the stable Homebrew formula, or stable migration pins.

## Changes

- Preserve saved expanded-bubble sizes while assigning spare height to the session-list viewport instead of leaving a large gap below a short message. Extra space stays below list rows; it does not stretch row spacing or text. Existing message/card minimum priorities, automatic size limits, screen clamping, and compact layout remain unchanged.
- Keep the matched-results summary on one 18pt line. “Not shown” counts only matching rows beyond the 128-card display cap, not rows excluded by search. A search with no matches reports zero without changing the existing empty-state distinction.
- Distinguish the representative status count from the total session count in English, Korean, Japanese, and Simplified Chinese. The total remains the unfiltered session total; a zero representative count is not replaced with the total. Status selection and aggregation semantics are unchanged.
- Preserve the full displayed status and result-summary text in tooltips and accessibility labels when narrow windows visually truncate them. Existing CLI feedback still takes precedence over the representative status text.
- Leave message scrollbar behavior unchanged: no scrollbar suppression or geometry correction was added without native overflow evidence.

This beta inherits beta.1's simplified settings, explicit beta-update consent, clearer session/connection wording, four-language Quit help, and the published v0.4.12 discover/start performance correction. Quit stops Desktop Pet only; Herdr and Tern keep running, and automatic-start preferences remain unchanged. Changing beta-update consent does not itself install or restart the app.

## Validation and known limitations

Before the beta.2 version cutover, the bubble-change candidate passed targeted allocation, screen-clamp, full-source aggregation and filter/cap regressions, a temporary four-locale formatter smoke, the complete native workspace suite (including the main-thread AppKit composer harness), Rust formatting checks, and neutral native build/package. The temporary formatter smoke was removed. Source review covered the layout and summary changes. These are prior-candidate regression and review results, not claims that final beta.2 metadata, tagged packaging, or publication gates have already passed.

The integrated local beta.2 candidate subsequently passed TypeScript checking, 62 tooling/web tests, the full arm64 native workspace suite and main-thread AppKit composer harness, Rust formatting, version-pinned release-note admission, and optimized neutral build/package. Both arm64 executables reported `0.4.13-beta.2` and matched protocol 4 / observation 2 / API 1. Deep/strict bundle signature validation, all 72 signed deployed-file hashes, and the real Rubelia native rig validation passed. This local package was built before the release commit; exact tagged-source provenance and public bytes remain the release workflow and download-verification gates, not inferred from that local build.

The separately staged candidate bundle passed signature verification, but helper discovery rejected its temporary path with “executable has no supported verified installation owner”. It was not started, no app was installed, and the existing checkout bundle was not replaced. The screen was also locked. **Native visual acceptance and real-provider scenarios remain unverified.** In particular, actual bubble placement, long-to-short message scrolling, narrow-to-wide transitions, tooltip/accessibility presentation, saved-size persistence, provider-backed status/count comparisons, long-list search, and inline reply behavior were not observed. Automated regressions do not establish those native acceptance results, Core-to-Tern reconnection, fresh SDK binding, migration/retirement completion, or recovery on another computer.

Final beta.2 release-note admission, integrated gates, clean tagged packaging, public tag provenance, and published asset checks are separate release gates. The release workflow retains its refusal to overwrite any existing release or asset set, its six-asset publication contract, prerelease status, and non-latest publication setting; prereleases do not synchronize the stable wiki. No public asset hashes or final release identities are asserted by these source notes.
