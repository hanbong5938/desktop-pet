# Desktop Pet v0.4.16 release notes

## Preserve trusted HOME in the isolated installer helper

The actual approved recovery exposed an installer bootstrap defect after preflight: the detached helper cleared its entire environment, including `HOME`. The native metadata query consequently failed with `HOME must be an absolute path` before durable ownership acknowledgement or installation. The parent correctly retained an unknown outcome instead of claiming success.

The helper still uses `env_clear`, but reconstructs `HOME` from the operating system account lookup rather than inheriting caller-controlled HOME, startup/updater tokens or unrelated environment variables. The existing ownership ACK, lease, immutable plan/request, Stop-generation and installation guards are unchanged.

An unowned preparation is resolved through its matching helper's same-ID recovery cleanup, not replayed as a new installation or manually rewritten. Only a new approved operation may install the new compiled Stable candidate. This patch inherits v0.4.15's authenticated SDK validation-child and post-exchange namespace corrections.

## Preservation and verification boundaries

Original config/state, characters, settings, retained originals and Tern/window work remain authoritative. No Tern restart, plugin reload, consumer reinstall, native KV rewrite or profile adoption is part of this correction. Helper settlement, a separately approved ordinary Pet start and actual fresh Tern bindings are distinct evidence.

Existing releases, tags, assets and frozen notes remain immutable. Legacy migration authority stays at 0.4.12; legacy 0.3.16, contracts 0.1.0, protocol and qualified consumer pins are unchanged. Homebrew formulae are unchanged.

Final local gates, exact tagged CI and affected-machine recovery must be reported separately; source or release verification alone is not recovery success. The package is ad-hoc signed, not Developer ID signed or notarized.
