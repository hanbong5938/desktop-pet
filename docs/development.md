## Source development

**Current checkout is ahead of the published binary:** Auto and live host preferences are unreleased, source-only changes. Source app/helper capabilities are `{"protocol":3,"observation_mode":2}`; published v0.3.6 stays capability 1 and defaults to Herdr. `--prebuilt` and Homebrew do not gain these features from documentation changes. Build with `--source` for the contracts below; published consumer-route evidence above remains historical evidence for that release.

Building and manually starting the native app from this checkout does **not** require a Herdr plugin, patched host, or client-attach hook. On the supported Apple Silicon Mac, with Rust/Cargo, Bun, Node.js/npm, Xcode Command Line Tools and `codesign` available, build the packaged app; the following manual-start example assumes an existing healthy local Herdr server:

Existing host-less profiles stay Herdr and retain their lifecycle behavior: for Herdr-only independent operation, set `exit_with_herdr off` before `start`, as in [Pet without Herdr](../readme.md#pet-without-herdr). The separate host procedure below is **only** for optional managed plugin lifecycle and Herdr client-attach auto-start; a stock host does not gain `client.attached` by building the app, and Auto does not promise Tern auto-start.

Existing hosts refresh first; new hosts admit local-first then numeric ID order, and results return in request order. A rejected remote host does not prevent existing-host refresh or a valid local receipt. Normal subsequent polling retries admission; no extra retry loop is introduced. Limits are 64 hosts/request, 128 agents/host, 64 shared Herdr+Tern sources, and 64 parent windows. Per-host errors are bounded to 512 UTF-8 bytes (ordinary field/top-level error bounds remain 4096 bytes). JSON requests are 256 KiB excluding optional LF/CRLF; complete replies are 512 KiB including LF. Actual serialized host-reply bytes participate in both admission and offer size checks before pending/offer state.

Each source is window×host (`tern:<hex(window)>:<hex(host)>`), with the existing exact session key and separate native generation. Plugin observation generations track observed loss/recovery and host kind/address changes, not an authoritative transport connection generation; a reconnect wholly between polls is not guaranteed detectable. Rename and ordinary polling preserve keys. A higher parent epoch replaces every child; a higher host observation generation replaces only that child. Observed loss, disappearance, unavailable inventory or five-second freshness expiry makes that host Offline without inventing completion; recovery gets a larger native generation, including native-only expiry with unchanged plugin generation. Explicit disconnect/disappearance cannot reactivate with a non-increasing observation generation. Parent expiry makes all children Offline; another host's heartbeat does not refresh an unavailable child. Source IDs identify the same window×host on recovery; generations, not IDs alone, fence stale keys. At first route loss, offered local work becomes `unknown_delivery`, unoffered work fails `offline`, and neither is replayed; remote loss does not cancel local pending work.

## Native build and signing

After source installation, the native checks are:

```sh
bun run check
bun run test:native
```

Native hit-overlay blending uses typed subexpressions for compatibility with the release runner's Xcode 16.4 Swift compiler. Preserve these type boundaries when changing the overlay; source builds still require Xcode Command Line Tools.

Debug and release native builds require `codesign`. They ad-hoc sign **only** `rig-decode-worker` with `com.apple.security.cs.allow-jit=true` from [`native/rig/RigDecodeWorker.entitlements.plist`](../native/rig/RigDecodeWorker.entitlements.plist). Cargo tracks plist changes to rebuild and re-sign the worker. JavaScriptCore can JIT-compile the trusted decoder bundle, while the main app and native rig library receive **no** JIT entitlement; worker isolation, validation, and resource limits remain. `bun run package:native` reapplies the worker-only entitlement with the selected signing identity and verifies effective entitlements and strict worker/app signatures after outer-app signing. Failure to sign or verify **stops packaging**. Default ad-hoc packaging is local use, not Developer ID signing or notarization.

The rig bridge checks version and seven C layout sizes **before** handing typed asset/token inputs across the Rust/Swift boundary; initial motion remains borrowed sealed bytes copied by the native host, never a path lookup. The Metal renderer prepasses actual eye-white apertures with independent L/R/unsided stencil bits before stable-ordered color drawing in the same encoder. The CPU semantic hit and raster reference use matching ownership; no-white rigs keep their legacy iris rendering. A `RIG_PROBE_FAULTS` probe can run `--eye-stencil-checks --output ABS` to save real-pixel and semantic fixtures; this does not establish the cause of earlier cancelled/disconnected visual observations.

`scripts/build-rig-native.mjs` records bounded source/compiler/output hashes in `native/target/rig-native/release/rig-native.json`; packaging verifies source and output closure, embeds that build record at `Contents/Resources/rig-native-build.json`, preserves the independent update coordinator and checks its protocol/signature, then writes `dist/HerdrDesktopPet.app.rig-native.json` after signing with hashes of **all** deployed `Contents` files. The sidecar stays outside the signed app to avoid a self-hash cycle. The release workflow uploads a separately named `HerdrDesktopPet-v0.3.6-rig-native.json` asset alongside the unchanged app-only archive and its two checksum files; neither updater nor installer needs a new archive layout. Compare sidecar hashes to actual unpacked, post-signing app files before asserting deployed-byte provenance.

## Native localization

Native UI strings live in the static catalog [`native/src/i18n.rs`](../native/src/i18n.rs), with Simplified Chinese and Japanese catalogs in [`native/src/i18n/zh_hans.rs`](../native/src/i18n/zh_hans.rs) and [`native/src/i18n/ja.rs`](../native/src/i18n/ja.rs). Add each new UI message to every catalog rather than translating runtime values, paths, IDs, or pack-owned metadata. Preferences persist the canonical tokens `system|ko|en|zh-Hans|ja`; dialogue overrides accept `ko|en|zh-Hans|ja`, with independent drafts per locale. Keep CLI/patch validation strict while preserving the tolerant fallback for older saved preferences. `system` checks preferred OS languages in order: Japanese tags match case-insensitively; `zh`, explicit Hans and CN/SG regions resolve to Simplified Chinese, but explicit Hant or TW/HK/MO without Hans must be skipped for the next supported language (default English). External catalog metadata remains Korean for `ko` and English fallback for `en`, `zh-Hans` and `ja`; authored dialogue and its fallback belong to each pack.

When changing native text or CLI language contracts, keep the [CLI contract](cli.md), [English](../readme.md), [한국어](../readme.ko.md), [简体中文](../readme.zh-Hans.md) and [日本語](../readme.ja.md) READMEs, and the [English](usage.md), [한국어](usage.ko.md), [简体中文](usage.zh-Hans.md) and [日本語](usage.ja.md) usage guides aligned. These links describe the native app; maintain the promotional website's four translations separately.
