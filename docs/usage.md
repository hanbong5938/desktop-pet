# Desktop Pet — usage

An independent native macOS desktop companion. Rubelia reacts to touch, displays sessions from registered providers such as Herdr and Tern, and lets you reply when that source grants prompt capability. The app also runs without a host.

## Requirements

**This source checkout:** interrupted left-button capture recovers silently after the button is released, without inventing a tap reaction. Rebuild and install this checkout to use these changes; already installed release binaries are unchanged.

Compact and expanded bubble size requests are saved separately but shared by attached and standalone modes. The opposite edge/corner stays fixed during preview and completion on the display where the drag began; later attached layout follows the character. An edge changes one requested axis, although new wrapping can increase the other displayed minimum. Height is measured at actual screen/anchor-limited width without reducing the intrinsic width minimum used for persistence. Movement only along an edge's inactive axis, or a return to zero active displacement, preserves its request; completion reflows to the latest automatic/manual minimum, allowing growth or shrinkage. Expanded message and cards share one height budget, reserving the card/reply minimum and a message line before sharing the rest. Automatic layout keeps its overall height limit; manual requests do not use that automatic limit. Scrollbars hide when content fits and remain usable on overflow. A small screen clamps displayed size without discarding the requested size.

Attached placement keeps the entire bubble body outside the character's stable bounds, rather than avoiding only its head anchor. **Auto** retains the current side while that side can still fit the reply/control minimum; expanding tasks, opening a reply, and live content reflow do not restart the side search. The displayed size can be limited by that side's available space without overwriting the saved request. Attached resize previews and completion use the captured side's safe region and keep the opposite edge fixed. If no side can fit the minimum, the bubble uses a bounded, tailless, least-overlap fallback in front of the character's window; it does not move the character or change saved sizes to make room.

Opening a reply measures its attached layout before focusing it, and keeps the selected row, input, and caret in view. Reflow preserves the native editor, draft, and selection. During IME composition, content/layout changes wait instead of reparenting or resizing the editor; if the current window becomes unsafe after a screen or character geometry change, only a safe window-position recovery is allowed before composition ends.

Outside an active gesture, reflow updates a resize cursor only while the bubble is the actual pointer target; native text and controls own their cursors, and reflow does not reset the cursor over another window/character. Completing with zero size displacement still saves a changed actual standalone origin; unchanged request and geometry do not write preferences. Active reply IME composition prevents starting a resize or **Restore automatic size**. If composition begins after pointer-down, preview pauses; release/cancellation ends tracking but postpones save and pending updates until composition is safe and tracking ends. Cards and drafts stay put. Completion calculates from the latest content, locale, layout and screen clamp and saves once. On save failure, previous size requests, actual standalone origin and pending state are restored without a ghost save, though newer content can change the displayed minimum. Restoring automatic size preserves position, visibility, current mode and drafts; position/color reset does not erase size requests. The menu-bar icon cannot directly open settings while the reply has active marked text; finish composition first. Escape/outside click still closes the settings panel.

## Session search and ordering

Cards name sessions by observed terminal title, then named tab, then workspace/directory context; missing names have an explicit fallback and duplicates a visible discriminator. Hover for the full title, working directory and internal IDs. Title changes preserve selection/scroll; disconnected cards keep their last title and display **Offline**.

Matching titles or working directories do not mean the same conversation. **Local**/**Remote** describe source location; connected/**Offline** describe availability. A local source can be Offline, and retained cards are not evidence of a live connection.

Card selection chooses the reply target in Desktop Pet (Core), not the active pane in Tern. The character aggregates status across all observed sources, so it can differ from the currently focused pane.

**Search** trims surrounding whitespace and matches case-insensitive substrings in title, tab/workspace, agent, source display name, full working directory or fallback name—not IDs or socket paths. Search and **Status** filter intersect without changing the overall observed status or reactions. **Sort** offers **Stable** (original order), **Name**, **Source**, then independent **Running first** below a separator. Running sessions from all included sources lead, with the chosen sort within each group; the closed menu and accessibility value include both choices. This is not sorting by every status. The GUI shows at most 128 cards *after* filtering/sorting and reports omitted cards; CLI `sessions list --limit` is a **page size**, not the total row limit ([CLI](cli.md#sessions-and-agent-prompt)).

Initially Search is empty, Status **All**, Sort **Stable**, Running first off. Only successfully saved Sort/Running first survive restart; a save failure reverts controls. Search and Status remain memory-only. Filtering a selected reply away folds the field but keeps that session's draft in memory; clearing search does not reopen it. Enter/Command+Enter in focused Search never sends. Escape cancels active search IME first, then clears a nonempty query, then exits the empty field without collapsing the bubble. Search/reply composition independently defer structural list changes until unmark; live statuses keep updating.

## Inline replies and message delivery

Inline replies first shipped in v0.1.6; stable v0.2.0 fixed clipped native reply glyphs and Command-A/C/X/V clipboard dispatch. Expanding the bubble shows cards but no reply field initially, including **All**. Click a local agent card for its one-line field; clicking another folds the previous field and opens the next. Remote cards have read-only feedback, neither field nor Send. Committed newlines from typing, paste or import become spaces; IME preedit remains untouched until committed. **Enter**, **Command+Enter**, or **Send** submits, never during composition. **Escape** first cancels composition, otherwise folds just the field; outside-bubble click folds it except while composing, while another inside-bubble click does not fold it. Neither action collapses the bubble. Session drafts survive field/bubble folding in memory, not restart. Success clears/folds only the currently matching reply: edits or a changed selection during send preserve the new draft/open field. Failure or uncertain delivery also preserves draft and reply state.

During composition, selection, filter changes and structural row replacement wait without losing marked text. On unmark the latest filter and only a still-visible valid selection take effect; committed text stays with its original session and connection generation. Live status/send eligibility still update. The field has a visible border and opaque palette-derived background; the compact native Send button tracks eligibility, and changing theme preserves draft/preedit.

For Herdr cards, delivery uses **only** the selected local Herdr source's `agent.prompt` API—not a global CLI, shell, SSH or raw pane input. Excluding local observation, an offline source, stale/unready session or unsupported server disables send; `unsupported_method` is reported, not worked around. Remote cards, including retained ones, cannot prompt. Handle approval/questions in the actual terminal. `agent.prompt` was verified with Herdr 0.9.2; local-observation floor 0.9.0 does not prove the running server supports it. Submission ACK is **not** agent completion. No automatic retry: check uncertain delivery before manually sending again. The API addresses the current pane occupant without an atomic expected-session guard, so instantaneous occupant/session replacement remains possible. See [CLI session identity and delivery](cli.md#sessions-and-agent-prompt) for automation, not a GUI fallback.

Tern replies use the registered adapter’s revalidated **one-shot `agents:ask`**, never Herdr fallback, shell or PTY injection. `prompt_accepted` / `accepted_may_be_queued` proves SDK acceptance only, not model delivery or completion; do not replay an offered or uncertain ask. Local window and grouped host inventory preserve adapter-authorized locality; remote host cards are read-only and Tern never grants worktree-removal capability. A window source expires after five seconds; stale/missing windows become Offline while Auto/no-adapter keep running. Polling splits inventory into four cooperative zero-delay callbacks and exchanges a fresh result immediately after ask; an individual SDK call or OS preemption can still exceed callback budgets, so no latency/stability guarantee is implied.

## Visibility and menu-bar recovery

Character (`show`/`hide`/`toggle`) and **Bubble → Bubble visible** (`show_bubble`/`hide_bubble`) are independent. Both on attaches the bubble; character only hides the bubble; bubble only makes a tailless movable standalone bubble with cards/replies; both off hides the windows but keeps the app/Herdr session running. **Close Bubble Window** changes saved bubble visibility, never deletes sessions or their in-memory drafts. Canceling its context menu preserves card selection/drafts. **Settings…** and **Close Bubble Window** are disabled and rechecked during active reply IME; finish composition and reopen the menu. Reopen at **Bubble → Bubble visible** via character/standalone-bubble contextual Settings or visible menu-bar icon. A standalone bubble's contextual menu also offers **Show Character**.

Hiding the character does not alter saved bubble visibility. First detach without a saved standalone origin takes the **actually applied attached bubble body's** position, not a merely computed position; if the character starts hidden, ordinary attached layout supplies the fallback. Its origin is saved separately from character position, and later detachments use it even during marked text. Background drag moves only that bubble; re-show attaches it, re-hide restores its origin. Compact/expanded changes, replies and remeasurement preserve it except screen clamping; a removed display/layout change recovers offscreen placement. Selection, view/reply state and drafts survive hide/show this run, not restart. Placement changed while standalone takes effect when reattached without moving the standalone origin. `reset` clears the old standalone origin, reseeding from newly applied attached layout as needed, without copying character coordinates or changing visibility. Marked reply text delays hide/show/placement/reset origin commitment until unmark; a newer reset supersedes an old origin. Composer callback observations retained marked text, committed draft and selection, not physical IME/focus certification.

**Current source: Settings → General → Visibility** offers **Always show** (default since stable v0.2.0) and **Only when recovery is needed**, independent of window visibility. In recovery-only mode the icon appears when **both windows are hidden** or **full-window click-through** is on; it is absent for interactive character-only, standalone-bubble-only or both-visible states and for alpha click-through alone (unless both hidden). Always-show keeps it visible in all those states. Neither mode displays an icon during shutdown; alpha pointer polling alone does not trigger recovery. Right-click/Control-click icon offers **Show and Enable Character** only when recovery is needed: this shows the character and disables full-window click-through, preserves bubble visibility and alpha click-through, and reattaches a visible bubble. Recovery-only hides the icon after that menu closes; CLI `show` only shows the character and does not show the bubble. The original `bf23ced` local preview's conditional icon is historical, not a preference inherited by today's profiles ([preview record](migrations/unreleased.md)).

`preferences.json` stores `menu_bar_mode` as `always` or `recovery_only`; missing key defaults to Always show even for an old conditional-preview profile. Successful changes apply immediately, survive restart/other saves and preserve unknown fields. Failed saves leave prior mode/icon; changing mode does not change visibility, click-through, positions, drafts or lifecycle.

**Current source: Settings → General → Customize icon → Choose image…** imports a **static PNG** (≤4 MiB encoded, ≤1 million decoded pixels). **Customize icon** starts collapsed; the preview and current icon status remain visible, as do import/load/save errors when the controls are folded. Animation, corruption, truncation and full transparency are rejected. Its original colors aspect-fit inside 18 pt with 1×/2× Retina representations. A successful managed copy in the config directory's `menu-bar-icons/` is referenced by optional `preferences.json` `menu_bar_icon.asset`; the source file can then move. Back up this directory with `preferences.json`, `lifecycle.json` and `characters/`. Missing preference shows the template pawprint. Import verifies **every PNG chunk CRC** (including ancillary chunks and IEND), IDAT zlib Adler-32 and exact inflated scanline length for the color/interlace passes before native decoding. Copies publish atomically without replacing existing files. A legacy interrupted private temporary hardlink is repairable only by explicitly reimporting the **identical valid PNG** when it is a confirmed owned, private, same-inode alias; no startup sweep or repair of arbitrary links, other files or corrupt PNGs. ## Worktree removal

In the expanded bubble, right-click/Control-click a **card header** for that card even if another is selected; right-click/Control-click the **background** targets the selected card *when the menu opened*. With no eligible selection, **Remove Worktree…** is absent. The menu identifies the target; native input/other control menus remain native. **Close Bubble Window** only hides the bubble.

The confirmation names repository, **exact checkout path**, and tab/pane counts for the **entire workspace**, not only the card. Removal closes all its tabs/panes, terminates their agents/processes and removes the linked checkout **including ignored files/build outputs**. It does not remove the main repository or Git branch and offers no Trash/undo. **Cancel** is first and default; Return, keypad Enter and Escape cancel. **Remove Worktree** is a distinct second action. If native alert setup cannot establish Cancel as default after layout, removal aborts. Review an owned disposable checkout and all affected files/processes before acting.

Only live, coherent local sources with unambiguous valid linked-worktree metadata are eligible: never main roots, remote/retained/offline cards, missing/malformed metadata or older servers without it. Unsupported `worktree.remove` reports an error rather than invoking Git/shell/SSH or forcing deletion. Active IME disables removal and is rechecked before submission. One operation at a time freezes the chosen target; after confirmation it rechecks against a fresh snapshot and sends exactly one `worktree.remove` with `force: false`, not a retry or optimistic row deletion. Dirty tracked/untracked files or locks can cause server refusal, while ignored files **may still be deleted**. Five-second watcher refresh governs visible rows; feedback persists after selection/row/window changes. A write with uncertain result requires independent server/worktree inspection **before** any manual retry. The request names `workspace_id` and has no atomic expected-checkout/generation CAS: client revalidation cannot eliminate restart/rebinding races. The [CLI inspect/token contract](cli.md#worktree-removal) adds a 60-second one-use inspected target and separates upstream ACK, later pane+session absence observation, and actual filesystem proof; do not use a live checkout to try it. Historical beta observations are not stable physical-input certification ([record](releases/unreleased.md)).

Eligibility additionally requires the registered source’s worktree-removal capability and locality; provider names or local-looking paths cannot confer it. Tern has no removal capability.

## Dialogue editing

Choose **Characters → Edit dialogue…** to open a separate resizable dark-theme editor, default content 760×560, minimum window 620×480. Choose any available character **and authored revision** without activating it, Korean (`ko`), English (`en`), Simplified Chinese (`zh-Hans`) or Japanese (`ja`) independently of UI language, and one of eight events: idle, running, waiting, unknown, head tap, body tap, petting, observed task completion. Controls sit at top, events left, editing and expandable original reference center, fixed status/actions bottom; hover truncated character names/errors for full text. Unsaved entries have badges. Without an override, the editor initially shows original authored text and the separate reference for comparison. User text replaces only that dialogue entry, not observed counts/status transitions, reaction timing or disconnection notices.

**Save dialogue** / **Command+S** saves one language/event, up to **2048 UTF-8 bytes** (not characters). Blank/whitespace-only removes an override; fallback remains pack/default/status text, not a hidden bubble. A saved override for the active character ID refreshes applicable bubble text even if editing a historical revision; editing another character never activates it. **Reset this entry** confirms unsaved draft loss; **Reset all character dialogue…** always confirms and removes all four language overrides. Drafts are isolated per character/language/event and survive context or UI-language changes and close/reopen this run, but only saves survive restart. **Command+Z** / **Shift+Command+Z** are contextual undo/redo. Failed saves retain draft and previous committed text.

Overrides are in `preferences.json`, **not pack files**. Built-in/imported characters key by ID and share across revisions, updates and restores. External `--assets` uses a separate canonical-path namespace; its active identity captured at activation remains editable if its source folder is renamed during this run, but a changed path on restart does **not** migrate stored overrides. If both managed registries are corrupted and the store falls back to read-only, built-in original text remains readable at the current listing generation without activating/repairing the registry; unavailable managed revisions do not become available.

External saves never silently overwrite an editor draft: stale revision/entry conflict blocks Save. **Reload saved** explicitly takes the latest committed text; **Rebase draft** retains local text against a new baseline for revalidation before saving. Conflict preserves text, focus/selection and undo; marked IME text defers reload/rebase until unmark. The exact `(target, reference)` selection or unavailable reference and draft stay put rather than silently switching revisions. First ready metadata hydrates an untouched field even when focused; raw premetadata edits (including whitespace and IME) survive and deferred hydration settles after unmark without overwriting subsequent focus/selection/undo. Automatic polls keep cached metadata errors; explicit reopen/selection or a new read may retry once. CLI targets are entire identity JSON, authored reference/generation and optional baseline guard the same safety boundary; [dialogue CLI contract](cli.md#dialogue). These conflict controls were introduced after v0.2.0/v0.2.1, not retrofitted to those binaries.

## Character packs

Rubelia (`default@0`) is the **only bundled character**; optional PNG/rig and wardrobe packs are in the separate [character gallery](https://hanbong5938.github.io/herdr-characters/). Open **Characters → Browse Characters…**, a separate retained resizable native browser. Search names/IDs and official tags; filter **All**, **Installed**, **Official Catalog**. Static portraits are previews, not pack archives, and browsing never downloads archives. Network/catalog failure leaves bundled and locally installed packs manageable but disables official download; unsupported formats cannot Download & Apply. An eligible published official card's **Download & Apply** explicitly requests verified download, install and activation. Official/installed packs sharing an ID use **one card across filters**, not duplicate cards. Only an actually active installed revision shows **Active** in Installed/Official Catalog. Installed cards use local portraits and retain selection, inspect/diagnostics, update/remove and historical restore; matching a manually imported ID to a catalog entry proves neither provenance nor version and never silently overwrites it. Remote 1024 × 1024 rig portraits are supported within the **4 MiB encoded and decoded** budgets, with pack validation limits unchanged.

Clicking an installed card/revision **stages a candidate only**; review the fixed footer and **Apply** to select. **Cancel** clears an unsubmitted candidate. Closing either window preserves the candidate, and reopening browser preserves search/filter. **Import** of a folder/`.herdrchar` alone neither stages nor activates; CLI `pack select ID` immediately selects the latest revision and `pack restore ID --revision N` an existing historical revision without UI Apply. Removing an active pack returns to Rubelia. Built-in `default@0` cannot be imported, updated or removed. Closing browser does not cancel a download; **Cancel download** stops changes only before commit.

While pack mutation is pending, Select/Apply/Cancel/Import/Update/Remove/Restore are blocked but read-only Inspect/diagnostics remain. Stale rendered card changes during composition are blocked; Cancel and Inspect can remain available when no pack mutation is pending. Picker/confirmation returns recheck busy state and listing generation instead of silently rebasing. Pack-store lock contention can briefly show portrait loading; true preview failure is an error. When busy → idle, installed-card Update/Remove/Restore eligibility refreshes without replacing the card/generation; Inspect remains available. Canceled/failed operations retain candidates. A rejected **unsubmitted** request differs from uncertain **submitted** work: read the full operation ID from footer tooltip/diagnostics and use `pack status OPID`, never blindly repeat. The most recent operation details remain in diagnostics after Apply or a new candidate. Successful inactive import/update/remove is complete without renderer activation; live character versus saved selection mismatch is shown separately from completion. Native activation can fail after install/save, so those facts are distinct. The **completed-success character-pack operation summary card is hidden**, but diagnostics remain; candidates, errors, in-progress, failed, canceled or uncertain outcomes still show. With no candidate, meaningful feedback is titled **Operation**. This does not hide validated **session** success.

Pack CLI accepts positional IDs (no `--id` for select/restore) and optional operation ID, expected generation, finite wait/no-wait; offline default mutation completes synchronously, explicit async/finite waits require a running daemon without secretly starting it. ACK is not commit/native apply, finite wait has one post-ACK absolute deadline including sleeps/status/decode, and a no-wait already-terminal failure exits nonzero. Keep an ID and inspect status rather than retrying uncertain work; there is no URL/catalog CLI to create official browser operations. See [pack commands, operation states and safety](cli.md#pack-commands-and-existing-boundaries), not a second command table. Character creation and templates are covered in [development](development.md#character-authoring), not here.

## Observation sources

In the current source UI, expand **Settings → Connection → Connection settings** (collapsed initially) for registered integrations' observation controls; these are provider-owned rather than a separate core **Observation scope** section. Published v0.3.6 uses **Settings → Observation sources**. Remote Herdr observation applies to Auto/Herdr, not Tern-only; hiding provider controls does not erase saved choices.

The following remote-machine controls and behavior describe the published Herdr workflow; they do not establish a separate observation panel in the current neutral Core.

Remote observation first shipped in v0.1.6; stable v0.2.0 included compact observation settings, copy-only reconnect and corrected standalone remote-only watcher startup. The local **This Mac** switch starts on and **Remote machines** off. For remote use, first add and authenticate an SSH machine in your **interactive terminal** following [Herdr's saved-machine guide](https://herdr.dev/docs/0.9.2/connecting-machines/) (for example `herdr machine add workbox`), including any prompted remote server setup. Then enable Remote machines and explicitly select an enabled saved profile under **Machines to observe**. One profile observes **one saved remote Herdr session**, not its whole host. Merely registering/attaching does not select it. Run the pet on the **local Mac** whose desktop you intend to display; the compatible remote Herdr server does **not** need the pet app/plugin. The local CLI polls selected remote profiles.

In Herdr-only mode (with the registered Herdr adapter), for remote-only operation, optionally run `desktop-pet settings set exit_with_herdr off` using the installed native CLI **before the first pet start** when no healthy local server exists, to avoid the 30-second lifecycle exit while configuring; turn it on after remote polling is healthy if desired. Auto/no-adapter does not need this workaround. This setting requires no remote plugin or Herdr plugin action. Disabling **This Mac** excludes local cards but **does not** unregister a local lifecycle endpoint or override confirmed-disable shutdown in Herdr-only mode. The saved-machine catalog refreshes every **5 seconds**, even when Remote is off; selected enabled profiles are polled every **5 seconds** when on. Selection survives restart and Remote-off; profile rename preserves it, while disabling/removing a profile excludes it without stopping its processes. Local and each remote source have separate card labels/identities even when session IDs match.

Rows separately show name, saved session and state; long diagnostics wrap and panels scroll. Settings distinguish initial catalog lookup from confirmed empty, and failed refresh retains the prior list with a stale warning. Remote-off displays **Observation off** rather than a former success. States also distinguish no selection, paused, checking, observing, unavailable and disabled. Controls keyed by opaque profile ID preserve focus/scroll through polling/rename and clamp scroll when the list shrinks; labels/accessibility names are localized and **How to register**/folded diagnostics are read-only. Source switches/selected profiles determine cards, counts, overall phase and completion/outcome reactions; Status card filter only changes which included cards are shown. All sources off produces **Unknown**, not a deliberately excluded source's disconnection warning.

Polling can miss transitions shorter than five seconds, including brief completions. On loss, last cards remain **Offline** and count as unknown, not live; the first fresh snapshot after reconnection/reselection is baseline, not replayed completion. For authentication, find ID with `herdr machine list`, then run `herdr machine reconnect '<profile-id>'` **yourself** in an interactive terminal after replacing the quoted placeholder with the exact ID. **Show error details** expands read-only diagnostics; **Copy reconnect command** copies a safely quoted command with feedback but never runs it. The app never answers credentials, installs remotely or falls back to local polling for a failed remote profile; remote cards stay read-only. Local observation needs Herdr ≥0.9.0; remote needs the **local CLI** supporting saved-machine API forwarding (`herdr --machine <profile-id> api snapshot`, documented in [Herdr 0.9.2 CLI](https://herdr.dev/docs/0.9.2/cli-reference/#saved-ssh-machines)) and a compatible running remote server. Missing/incompatible CLI is shown in settings, not a new local version floor. `client.attached` auto-start requires the **separate patched host**, not simply a 0.9.3 manifest floor; see [host integration](https://github.com/hanbong5938/herdr-desktop-pet/blob/main/integrations/herdr/README.md).

## Lifecycle and plugin actions

Core owns common lifecycle persistence and `auto_start` (default on); registered integrations own their extra keys. The Herdr owner initializes `exit_with_herdr:true` **only when `lifecycle.json` is absent**, atomically in the shared profile writer on its first lifecycle write. An existing lifecycle file missing that key reads false; explicit false remains false. Legacy boolean `enabled`, including false, migrates to `auto_start`. Endpoints, startup metadata and unrelated owner fields survive; these settings live in `lifecycle.json`, not `preferences.json`. Bad JSON/values error rather than reset defaults, and failed saves preserve saved/runtime policy. Auto/no-adapter remain alive without Herdr; the following Herdr endpoint/disconnect rules apply only to Herdr-only selection.

With auto-start on, server startup or **successful shell/terminal client attach** starts an absent pet; automatic `ensure` with it off reports a successful skip for absent pet, may register an already-running endpoint, and never reveals a hidden pet. Manual `start` works with auto-start off without changing settings. `stop`/native **Quit** end only this run including a pending startup; `restart` starts manually and preserves settings/position/scale. If auto-start stays on, the next qualifying event can restart it; disable the switch to prevent that. Herdr plugin disable/unlink is a **separate host action**, not a preference. Stock Herdr 0.9.0/0.9.3 do **not** implement `client.attached`; the supplied patch on official 0.9.3 or a future actual hook-supporting host release is required. An unknown-hook link warning is not success; follow [host integration](https://github.com/hanbong5938/herdr-desktop-pet/blob/main/integrations/herdr/README.md).

A valid `plugin_list` with no `desktop-pet` on a **new** local endpoint means not installed there, **not** disabled: local snapshots/selected remote profiles can still be observed. Explicit `enabled: false` detaches that endpoint. Once this daemon has observed an enabled **or disabled** entry on an endpoint, later absence means observed unlink; memory persists across checks/reconnects this run, resets on new daemon. If **all registered local endpoints** are confirmed disabled/unlinked, exit is **immediate**, even with a healthy remote or `exit_with_herdr` off. Initially absent entry does not qualify. Otherwise, with exit on, losing the **last healthy server connection** (including initially no reachable server) gives **30 seconds** for a healthy connection to return. Client detach is not server loss; stale endpoints/failed retries do not extend grace. Exit off cancels countdown; enabling it while disconnected starts a fresh 30 seconds. A remaining healthy connection keeps the app running; manual pet with exit off can run without Herdr. Changing auto-start does not stop/show the current pet; `show`/`hide`/`toggle` affect visibility only.

For a running, enabled Herdr host, e.g. `herdr plugin action invoke status --plugin desktop-pet`, `settings`, `restart` or `stop` use the same action-invoke form. **Current source:** plain native `desktop-pet settings` and the existing Herdr plugin Settings action open the **same unified Settings tab**, not a separate lifecycle-only window. If the pet is offline, explicit `settings` starts the selected profile with its saved host while preserving hidden character/bubble state; source offline `settings` may also take `--assets PATH`. Use the matching config/state paths. The native entry works without a Herdr host; the plugin action requires that host. **Published v0.3.6** retains its older separate lifecycle-only settings window, including when the pet is stopped.

Native `settings get`, `settings set auto_start off`, and `settings set exit_with_herdr on` remain the lifecycle-only CLI contract: get/set return structured JSON, set accepts core `auto_start` or registered adapter-owned keys and exact `on|off`, launches no pet, and rejects malformed inputs/save failure without resetting other settings. `status` reports both. Other action IDs include lifecycle `start`, `ensure`, `stop`, `restart`, `status`, `settings`; visibility `show`, `hide`, `toggle`; `passthrough`, `alpha_passthrough`; bubble `show_bubble`, `hide_bubble`, `bubble_above|below|left|right|auto`; geometry `reset`, `bigger`, `smaller`. The [native automation contract](cli.md#english) distinguishes imperative actions, absolute presentation/preferences, private socket, and family-specific operation-status recovery; there is no public `orchestrate` or HTTP service.

## In-app updates

In current source, update options start collapsed.

**Existing-owner recovery:** see the [explicitly approved one-time recovery above](#existing-applications-owner-explicitly-approved-one-time-recovery). Once canonical recovery is complete, normal updates remain at the private owner. Beta opt-in, stable-only policy and Homebrew restrictions are unchanged.

If in-app update is unavailable, keep existing settings and characters. **Open official install instructions** opens the validated release's official page, not an unexplained archive or an automatically executed installer. Follow the procedure for the actual installation owner; do not delete profiles, rerun an old installer or start with guessed/default paths. A Tern control error is now shown as its actual backend diagnostic rather than an `alpha_passthrough` schema error; ordinary status/error responses never count as fresh binding evidence.

**Settings → App updates** keeps **Automatically check for updates** (default on), **Check now**, running version/origin, policy-specific last successful check, status/errors and available origin-specific actions visible. In current source, expand **Show update options** for **Receive beta updates** (default off) and its warning, then use **Hide update options** to fold them; folding preserves the policy, and **Beta updates enabled** remains visible when beta is on. This disclosure never hides update failures or available update/recovery actions. Stable-only checks select official stable releases; beta opt-in selects the highest eligible stable/beta SemVer, with a final release ahead of its same-base beta and no downgrade on opt-out. Automatic checks occur at most daily while open, with separate stable-only and beta-inclusive timestamps. Changing beta policy invalidates the prior candidate and checks under the new policy only when automatic checking is on. Toggles and checks never install/restart, refresh Brew metadata or change Git; an action requires separate native consent. Checks do not change lifecycle, installation, running image or selected profile, but successful checks may write the policy-specific timestamp cache (`last_update_check` / `last_beta_update_check`) in `preferences.json`; they are not byte-for-byte read-only.

- **Standalone:** verifies pinned neutral release bytes, stages and atomically replaces the account-home app under native installation admission. The shared locator identifies the installation, not a host manifest or socket-parent guess. A verified existing owner can be reused; live profiles/reservations block unsafe replacement. Normal neutral updates never invoke the Herdr plugin manager; legacy-owner retirement belongs only to the originally approved [migration route](migrations/desktop-pet.md).
- **Homebrew:** retains the captured manager/prefix and explicitly names the approved stable formula/version. Physical replacement is the formula's **Cellar subtree across kegs**, not the entire prefix. Beta targets are not authorized through this formula; no automatic channel conversion or ownership takeover occurs. Checks themselves only read cached metadata.
- **Local checkout:** explicitly rebuilds current on-disk files without Git pull/reset/ref change. An identical rebuilt executable is acceptable only when the replacement instance is actually ready.
- **Verified external installation:** a signed protocol-4-compatible already-installed package may offer **Apply installed update** without rerunning an installer, including an explicitly accepted eligible installed beta while stable-only policy is selected. Manual/unknown origins are not silently relabeled as Herdr or Homebrew.

Consent and Prepare recheck unsaved drafts, IME, pending work and gestures, then freeze mutating controls while the **exact original instance still runs**. This includes dialogue undo/redo and browser search/filter/local-folder actions through AX/internal callbacks; safe cancellation/reconciliation restores native control states/editor history. Helper ownership **ACK is not installation, Stop or Quit**: only the matching final visible/prepared ACK after accepted Prepare transfers consent, and only the matching reserved Stop with its accepted reply fully delivered commits updater shutdown. Slow staging runs on a worker with responsive helper UI; the native 30-second deadline means waiting, not cancellation. Failed reply thaws original without launching installer; ordinary user Stop/Quit wins over updater restart. Proven failure **before helper spawn** is retryable after repair and a fresh Check; spawned/uncertain ownership is blocked until evidence-based recovery.

A standalone **signed helper**, selected config/state and custom assets must lie outside the physical mutable installation; another live profile sharing it prevents replacement. Helper preserves selected profile, backend and assets, verifies new instance's actual readiness and distinguishes **installed** from **applied**; Applied does not mean latest public release. Candidate startup requires the exact durable **image and installed origin** pair, not a pin reconstructed from current disk. Compatible partial markers can be repaired without manager replay; incomplete pins, drift and uncertain manager execution remain blocked. A separately verified Original can only be restored under durable failed-update purpose, not reported as an upgrade. User Stop forbids revival but permits reconciliation and release of a fully proved safe stopped transaction. A proven **NoSpawn** interruption with the exact original still ready leaves it running/thawed; a later fresh successful Check can offer a new plan without erasing history. Never automatically replay manager or silently delete journals. Offline `update-status` reports retained records, not live process/signature proof; use the verified private helper's `status` and explicit leased `recover` per [updater status/recovery contract](cli.md#app-update-status-and-recovery).

Legacy protocol-1/2/3 evidence remains preserved and blocked; use only the retained signed matching helper, never convert it to v4. Neutral journals use `updates-v4/` and actual OS account-home `.desktop-pet-updates`, alongside old `updates/`/`.herdr-updates`. Lock order is old global gate → new global gate → sorted installation roots, with legacy stop-generation checks. Historical bridge A→neutral B required separate consent and verified v4 `migrate-legacy --plan ABS`; that is not the upcoming normal route. The upcoming single approval covers automatic same-profile Commit, fresh consumer rebind/native receipt and only then approved retirement. Notes and candidate packaging establish neither publication nor acceptance. See [migration and recovery](migrations/desktop-pet.md).

## Configuration and troubleshooting

- Select **explicit `--config-dir`/`--state-dir` > `DESKTOP_PET_CONFIG_DIR`/`DESKTOP_PET_STATE_DIR` > default-profile record > neutral XDG defaults** (`~/.config/desktop-pet`, `~/.local/state/desktop-pet` without XDG overrides). Core never implicitly uses `HERDR_PLUGIN_*`; only the Herdr wrapper interprets its host injection and forwards explicit paths. Config holds lifecycle/preferences, characters and menu-bar-icons; state holds lock, private `control.sock`, daemon log and update evidence. Back up and use both matching actual paths. `--herdr-socket ABS` is a registered Herdr-adapter backend option, never the private control socket; with no adapter core does not normalize/register it. See [profile/discovery contract](development.md#profiles-and-installation-discovery).
- In Herdr-only mode (with the registered Herdr adapter), if the pet disappears after about 30 seconds without a healthy server, inspect `settings get` and `status`, set `exit_with_herdr off` before restarting in the same config/state profile, and distinguish hidden windows from an exited daemon. Explicit disable/unlink of all registered local endpoints is a separate immediate shutdown in Herdr-only mode, not overridden by that switch. Auto/no-adapter/Tern do not use this Herdr exit policy.
- Hidden windows or full-window click-through do not mean startup failed: use menu-bar recovery above. If not running after `plugin link`, inspect `client.attached` warnings, invoke manual `start`, inspect daemon `status`/log; `auto_start` off intentionally skips automatic startup. Linking a running host does not itself launch the pet. For client-attach host patch, isolated deployment and actual hook confirmation follow [integrations/herdr/README.md](https://github.com/hanbong5938/herdr-desktop-pet/blob/main/integrations/herdr/README.md).
- On `Herdr watchers are shutting down`, inspect inherited `HERDR_SOCKET_PATH` / `HERDR_CLIENT_SOCKET_PATH`, actual CLI executable/version on `PATH` and server owning that socket. `herdr plugin list` against a **different server** does not diagnose the daemon's endpoint. Target the same CLI/socket/session; for remote errors also check saved-machine forwarding/version/selected profile. The patched host enables auto-start but does not install this plugin on every server.
- For remote errors see [Observation sources](#observation-sources): profile status, interactive authentication/reconnect and compatible forwarding CLI. Launch the GUI on the local Mac, not over SSH on a remote host expecting local windows. `agent.prompt` limitations and remote read-only behavior are [above](#inline-replies-and-message-delivery).
- Default and `--prebuilt` use the exact published pinned assets of immutable v0.4.7 (historical v0.4.0/v0.4.1 checkouts retain their own pins). Failure never silently builds source; explicit `--source` builds the selected core checkout, including the actual public v0.4.7 tag. **Core v0.4.7:** [Desktop Pet v0.4.7](https://github.com/hanbong5938/desktop-pet/releases/tag/v0.4.7), release `413584934`, source `52514da5115f09aac22de5429c08f7acdd993258` (2026-10-15T08:39:17Z). Six anonymous assets, strict/deep signatures, protocol 4 / observation 2 / API 1 and exact 68-file closure passed. Current observed acceptance: [v0.4.7 ledger](releases/v0.4.7.md). Pages is not yet observed; Wiki publication lacks dedicated `WIKI_PUBLISH_TOKEN`.
- Provider integration is Herdr's upstream responsibility; restart/reload existing provider sessions after installing upstream lifecycle hooks. The pet displays observed status and never infers provider outcomes. Refer to [release history](releases/README.md) for version-specific behavior and [host integration](https://github.com/hanbong5938/herdr-desktop-pet/blob/main/integrations/herdr/README.md) for host details.
