Desktop Pet + Herdr

Apple Silicon Mac, macOS 13+. Source builds require Rust/Cargo, Bun, Node.js/npm and Xcode Command Line Tools; prebuilt installation does not. The app is ad-hoc signed, not Developer ID signed or notarized. Herdr snapshots need a compatible local server (0.9.0+); replies separately need agent.prompt. Optional client-attach auto-start still needs the integration-owned patch and host instructions on official Herdr 0.9.3 or an actual hook-supporting host. Stock 0.9.0/0.9.3 lack that hook; plugin installation does not patch the host.

brew install hanbong5938/tap/desktop-pet
desktop-pet --version
desktop-pet start
desktop-pet status
# Optional Herdr lifecycle integration:
herdr plugin install hanbong5938/herdr-desktop-pet

desktop-pet --herdr-socket /actual/path/to/herdr-api.sock start — registered Herdr-adapter backend only, never the private control socket.

Desktop Pet / Auto

New profiles default to Auto. Connection lists registered providers and their actual connections, not installation detection; provider IDs are opaque and capabilities, not source-name prefixes or paths, authorize operations. Auto is simultaneous observation, not provider fallback. Remote sources are read-only; Tern prompts do not permit worktree removal. Submission acceptance is not agent completion.

desktop-pet profile show --json
desktop-pet start
desktop-pet status

Core owns common lifecycle persistence and auto_start (default on); registered integrations own their extra keys. The Herdr owner initializes exit_with_herdr:true only when lifecycle.json is absent, atomically in the shared profile writer on its first lifecycle write. An existing lifecycle file missing that key reads false; explicit false remains false. Legacy boolean enabled, including false, migrates to auto_start. Endpoints, startup metadata and unrelated owner fields survive; these settings live in lifecycle.json, not preferences.json. Bad JSON/values error rather than reset defaults, and failed saves preserve saved/runtime policy. Auto/no-adapter remain alive without Herdr; the following Herdr endpoint/disconnect rules apply only to Herdr-only selection.

See current usage, profile/discovery contract, and legacy migration for exact defaults, precedence, adoption and A→B migration. Copy the actual executable/config/state triple from status or Connection into Tern Configure, save successfully, then Connect. Existing isolated Tern/beta/custom profiles are preserved in place, never merged.

Desktop Pet + Tern

Install only the integrations you want. Herdr is a thin consumer; Tern does not download, build, install or auto-start the native app. Plugin updates/removal affect integrations only, never the shared app, profile or characters. Native updates do not reinstall Herdr plugins.

tern plugin install https://github.com/hanbong5938/tern-desktop-pet
desktop-pet profile show --json
desktop-pet start

Configure → Save → Connect: actual executable / config_dir / state_dir. No automatic profile merge, native install or startup.

Core / prebuilt / source

For prebuilt or source installation, use the core checkout, not a Herdr integration checkout. Default installation is prebuilt-only; download or validation failure never silently compiles source. --source explicitly builds only the current core checkout and uses its dist/DesktopPet.app.

git clone https://github.com/hanbong5938/desktop-pet.git
cd desktop-pet
# Immutable public v0.4.8 installer and assets:
git checkout --detach v0.4.8
bash scripts/install.sh --prebuilt

For explicit v0.4.8 source installation, use a separate checkout pinned to the actual public tag:

git clone https://github.com/hanbong5938/desktop-pet.git desktop-pet-source
cd desktop-pet-source
git checkout --detach v0.4.8
bash scripts/install.sh --source

Default and --prebuilt use the exact published pinned assets of immutable v0.4.8; historical checkouts retain their own pins. Failure never silently builds source; explicit --source builds the selected core checkout. 05 / GOOD TO KNOW

Frequently asked

A few things to know before you begin.

Does it run on Intel Mac, Windows, or Linux?

No. The native distribution targets Apple Silicon Mac with macOS 13 or later.

Does a successful message mean the agent finished?

No. You can submit a message when the server for your selected local session supports agent.prompt. Success means Herdr accepted it, not that the agent processed or completed it. Remote sessions are read-only.

Will it auto-start on client attach with stock Herdr?

No. Client-attach auto-start requires a host supporting the client.attached hook: apply the supplied patch to official Herdr 0.9.3 source, or use a host release explicitly supporting it. Stock 0.9.0 and 0.9.3 lack this hook.

Are other characters included?

No. Only Rubelia is bundled. Explore optional packs and their terms in the separate official character repository.
