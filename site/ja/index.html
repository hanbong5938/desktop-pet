ネイティブのデスクトップコンパニオン

エージェントのセッションをデスクトップで確認。ローカルエージェントに返信。

Rubeliaの吹き出しで観測されたセッション状態を確認し、選択したローカルエージェントにメッセージを送信できます。受理されたメッセージは、タスクの完了を意味しません。

Desktop Petをインストール ↗実際のアプリ画面を見る ↗

同じネイティブアプリを選択した共有または個別のプロファイルでTernに接続するか、ホストなしでキャラクターだけ起動できます。

Appleシリコン搭載Mac · macOS 13以降 · Rubeliaを同梱

01 / アプリ画面

イラストから、
あなたのデスクトップへ。

隔離されたオフライン環境でmacOSネイティブアプリv0.3.2を撮影しました。画面に接続中のセッションはありません。

02 / 主な機能

セッションを確認。
ローカルで返信。キャラクターと交流。

観測されたHerdrワークスペースとデスクトップキャラクターの3つの使い方。

01 / 状態確認◉

推測ではなく観測された状態を表示

吹き出しのセッションカードには、待機中・実行中・入力待ち・状態不明を表示します。エージェントの作業結果は推測しません。

02 / 返信↗

ローカルセッションにメッセージを送信

選択したローカルエージェントのカードから送信できます。Herdrによる受理は作業完了を意味せず、リモートのカードは閲覧専用です。

03 / 交流✳

触れると反応するRubelia

頭や体をタップしたり、頭をなでたりすると反応します。ドラッグで移動し、大きさも調整できます。

03 / DESKTOP PET

インストールと任意の連携

独立したネイティブ macOS デスクトップコンパニオンです。ルベリアはタッチに反応し、Herdr・Tern など登録済みプロバイダーのセッションを表示して、許可された送信先に返信します。ホストなしでも動作します。

公開状態: 過去の Herdr v0.3.6 は protocol 3 / observation capability 1 の公開版です。独立 Desktop Pet v0.4.1 と中立 Homebrew formula は公開済みです（protocol 4 / capability 2 / integration API 1）。匿名6アセット・署名・配備68ファイル、実際の Homebrew 0.4.0 → 0.4.1 更新、同一プロファイルの公開 wrapper による UI/control ready・Auto 4/2/1 を検証しました。新規 standalone 匿名導入でも実 OS home の Applications/DesktopPet.app と UI/control ready、Herdr 0／Tern 0 を確認しましたが、SDK の実アカウント証明ではありません。Herdr v0.4.0 は公開済みですが、生成アプリ69ファイルと失敗テストの profile／lock／symlink 6ファイルがソースに混入し、修正済み guard は不変ソースを拒否します。Tern v0.2.0 は公開済みで、保持する Core v0.4.1 pin は 4/2/1 と互換です。承認された修正 Core v0.4.2 + Herdr v0.4.1 と bridge v0.3.7 はまだ未公開・未受入です（修正台帳）。Tern private-window keychain／未サインインと OMP 18.10.3 NoModel／provider setup により、実アカウント検証と最終2ホストマトリクスは未完了です。Core Pages の配備と最新 Wiki 公開は未確認で、Herdr の薄いリダイレクト Pages も匿名確認は未完了です。過去の文書、タグ、アセットは変更しません。ネイティブアプリであり、ブラウザー上のランタイムではありません。

公開 core の導入コマンドは以下です。任意の連携は別途導入し、ネイティブアプリを自動インストールしません:

Desktop Pet + Herdr

Apple Silicon Mac、macOS 13 以降。ソース構築には Rust/Cargo、Bun、Node.js/npm、Xcode Command Line Tools が必要ですが、プリビルドには不要です。ad-hoc 署名で、公証されていません。Herdr スナップショットは互換ローカルサーバー（0.9.0+）、返信は別途 agent.prompt が必要です。任意の client-attach 自動起動には公式 Herdr 0.9.3 に連携所有のパッチとホスト手順を適用するか、実際にフック対応のホストが必要です。標準 0.9.0/0.9.3 にはフックがなく、プラグイン導入はホストをパッチしません。

brew install hanbong5938/tap/desktop-pet
desktop-pet --version
desktop-pet start
desktop-pet status
# Optional Herdr lifecycle integration:
herdr plugin install hanbong5938/herdr-desktop-pet

desktop-pet --herdr-socket /actual/path/to/herdr-api.sock start — registered Herdr-adapter backend only, never the private control socket.

Desktop Pet / Auto

新規プロファイルは Auto です。Connection は登録されたプロバイダーの実際の接続を示し、インストール有無を接続と扱いません。ID は不透明な値で、権限は名前の接頭辞やパスではなく capability で判断します。Auto は同時観測で、fallback ではありません。リモートは読み取り専用、Tern は返信のみで worktree 削除は不可です。受付はエージェントの完了ではありません。

desktop-pet profile show --json
desktop-pet start
desktop-pet status

Core は共通 lifecycle 保存と auto_start（既定 on）を所有し、追加キーは登録連携が所有します。Herdr 所有者は lifecycle.json が存在しない場合だけ、最初の lifecycle 書込みで共有 profile writer 内に exit_with_herdr:true を原子的に初期化します。既存ファイルにキーがなければ false、明示的 false も維持します。旧真偽値 enabled は false を含め auto_start に移行します。端点、起動メタデータ、他所有者のフィールドは保持し、preferences.json ではなく lifecycle.json に保存します。不正 JSON／値は既定化せずエラー、保存失敗は既存ポリシーを維持します。Auto／アダプターなしは Herdr がなくても動作を維持し、以下の Herdr 端点／切断規則は Herdr 専用選択だけに適用します。

利用ガイド、正確なプロファイル・探索契約、A→B 移行を参照してください。status / Connection の実際の実行ファイル・config・state を Tern Configure に指定し Connect します。既存の Tern・beta・custom プロファイルはその場で保持し、マージしません。

Desktop Pet + Tern

必要な連携だけを導入します。Herdr は薄い consumer です。Tern はネイティブアプリを取得・構築・インストール・自動起動しません。プラグインの更新・削除は共有アプリ、プロファイル、キャラクターを削除しません。通常のアプリ更新で Herdr プラグインを再導入しません。

tern plugin install https://github.com/hanbong5938/tern-desktop-pet
desktop-pet profile show --json
desktop-pet start

Configure → Connect: actual executable / config_dir / state_dir. No automatic profile merge, native install or startup.

Core / prebuilt / source

プリビルド・ソース導入は Herdr 連携ではなく core チェックアウトで実行します。既定はプリビルドのみで、取得・検証失敗からソースビルドへ黙って切り替えません。--source は現在の core だけを構築し、その dist/DesktopPet.app を使用します。

git clone https://github.com/hanbong5938/desktop-pet.git
cd desktop-pet
# 公開済み不変 v0.4.1 インストーラーと固定アセット:
git checkout --detach v0.4.1
bash scripts/install.sh --prebuilt
# 現在の v0.4.2 ソース開発は別の現在のチェックアウトで:
# bash scripts/install.sh --source

不変 v0.4.1 タグの既定／--prebuilt は公開済み固定アセットを使います。現在の main は v0.4.2 修正ソースで、v0.4.2 プリビルドは未公開です。公開 v0.4.1 と現在の v0.4.2 ソース開発を分け、後者だけ別 checkout で明示 --source を使います。取得／検証失敗をソース構築で隠しません。standalone prebuilt は 実 OS アカウント home の Applications/DesktopPet.app、承認された source は core の dist/DesktopPet.app を使います。admission は検証済み健全な既存所有者を再利用し得るため、推測した dist パスではなく導入器が示す実行ファイルを使います。共有 locator はアカウント home の .local/share/desktop-pet/installation.json に原子的に保存し、探索証拠であって権限ではありません。不正な明示パス／locator は fallback せず、実行ファイル、署名、capability、origin を再検証します。Brew は実際の formula／prefix を所有し、生存／予約中の導入を密かに引き継ぎません。

Legacy A: 0.3.6 → bridge 0.3.7（未公開・未受入）; explicit B: → 新規 Core 0.4.2 + 修正 Herdr 0.4.1（未公開・未受入）。Protocol-2 beta: 保持 helper → 固定 0.3.6 → A → B。使い捨てアカウント／VM が必要です。

05 / ご利用前に

よくある質問

使い始める前に知っておきたいこと。

Intel Mac、Windows、Linuxでも動作しますか？

いいえ。ネイティブ版の配布対象はmacOS 13以降を搭載したAppleシリコンMacです。

メッセージの送信成功はエージェントの作業完了を意味しますか？

いいえ。選択したローカルセッションのサーバーがagent.promptに対応している場合にメッセージを送信できます。成功はHerdrが受理したことを示すだけで、エージェントが処理または完了したことは示しません。リモートセッションは閲覧専用です。

標準のHerdrではクライアント接続時に自動起動しますか？

いいえ。自動起動にはclient.attachedフックに対応したホストが必要です。公式Herdr 0.9.3のソースに提供されたパッチを適用するか、このフックへの対応を明記したホストのリリースを使用してください。標準の0.9.0と0.9.3は対応していません。

ほかのキャラクターも同梱されていますか？

いいえ。同梱されるのはRubeliaだけです。追加パックと利用条件は別の公式キャラクターリポジトリをご覧ください。
